# 历史会话删除与工作区会话清理：使用流程

## 基本流程

Sessions 历史进入流程：等待工作区 hydrate，查询服务端布局并验证 Tab，必要时复用原始会话、创建恢复 Tab 或重建工作区；取得可进入的目标后由专用回调调用现有项目选择处理器，同步项目列表、工作区选择与临时分组展开。缺少路径、无代理 ID 的失效 Tab 或查询/创建失败时，不提前改变侧边栏；hydrate 失败时终止恢复，不误判为工作区已删除。普通通知入口保持通用导航。

1. 选择历史项并打开确认框。
2. 核对默认原始记录删除选项，确认后执行；打开弹窗本身不删除。
3. 删除工作区时检查关联会话是否允许清理，完成后更新列表。

## 异常与约束

- 正在使用的原始会话受服务端保护。
- 默认勾选是已确认的产品决策，不能描述成默认只隐藏或要求先手动勾选。
- 会话记录清理不等于磁盘 Worktree 清理。

具体实现与测试入口见[规格](../spec.md)。

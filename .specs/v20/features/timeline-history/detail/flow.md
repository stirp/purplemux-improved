# 按轮加载历史与长消息展开：使用流程

## 基本流程

打开 Agent tab 时聊天与终端独立初始化。命中同一 Agent 会话展示缓存时先显示记录，仍建立 WebSocket 重新校验；新的 init 替换展示缓存，之后恢复分页。服务端先发记录，再异步发统计；结束、切换或 resume 使旧缓存失效。

新会话尚未创建 JSONL 时，session-waiting 更新会话身份并清理旧会话已确认记录，但保留本地 pending 用户消息与附件占位，等待 init/append 确认。

1. 打开会话并展示当前数据。
2. 请求更早一轮记录，将返回数据与现有时间线合并。
3. 反复加载至无更多历史，并独立控制长消息展开。

## 异常与约束

- 会话列表刷新先检查文件状态，未变化时复用缓存；超过 30 秒不自动触发内容扫描。
- 文件变化时完整重读元数据；删除和读取失败按原流程忽略条目，并允许后续重试。读取期间发生变化的结果不缓存。
- 多个请求同时读取同一路径时共享消息元数据解析；Codex 单次扫描加载并发最多 10。统计读取失败仍可重试，关闭或切换界面的交互不变。

- 分页边界按对话轮次，不等同于固定条目数。
- 必须区分 Codex 旧模式替换行为与按轮增量模式。

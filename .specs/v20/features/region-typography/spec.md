# 设置中的区域字体调整

## 概述

为现有主要区域提供字体、字号、字色的独立设置，避免用户必须手写自定义 CSS。
需求来源见[区域字体需求](../../requirements/region-typography.md)。
本规格为已实现功能的回补，自动化通过与实机验收状态分别记录。

## 主要功能

- 设置 → 外观提供独立区域字体面板，原有自定义 CSS 编辑器继续保留。
- 覆盖 sidebar、tabs、messages、input、terminal 五个区域。
- 字体名称支持逗号分隔的回退列表；空字段恢复原有样式。
- 提供区域预览、应用、放弃修改、单区域恢复默认及全部恢复默认。
- 保存成功后更新当前界面并持久化；配置通知、重连及页面重新可见时同步其他客户端的区域配置。
- 终端通过 xterm 选项更新字体和前景色，字体加载后重新计算尺寸；区域覆盖在工作区和移动端组合点解析，登录终端不受影响。

## 边界与兼容

- 旧配置缺失 `regionTypography` 时使用空对象；不改变原有全局字号预设及终端主题默认值。
- 区域字号为绝对 px，优先于全局字号预设；恢复默认后重新使用原有规则。
- 自定义 CSS 继续作为高级覆盖机制；区域样式无 !important，注入变量位于用户 CSS 之前，允许覆盖。
- 不直接覆盖 SVG 样式；使用 currentColor 的图标可能继承父容器的字色。
  较大字号下桌面标签栏需增加最小高度以避免裁切。
- 固定颜色在浅色和深色主题中均生效；用户负责选择与当前背景适配的颜色。
- 使用查看设备的本地字体，缺失时回退；不上传字体，不枚举系统字体。
- 桌面侧边栏和桌面标签栏为本次对应目标；移动端共享消息、输入框和终端配置。
- ANSI 彩色文字保持终端主题定义的颜色。

## Review 修复验收（2026-10-03）

- RT-10：仅变更终端颜色时立即刷新可见缓冲区；值相同的主题不重复设置或重绘。
- RT-11：颜色文本无效时不展示伪造颜色，也不能用选择器悄悄覆盖无效文本；需先修正或清空。
- RT-12：区域和字段的键顺序不影响 dirty；等价配置不发送 PATCH。
- RT-13：配置广播直接携带去除认证秘密的完整快照；客户端按 updatedAt 接收新快照，旧 GET 不覆盖新配置。
- RT-14：保留服务端错误详情；action 依赖服务端写入校验，界面保留即时校验。
- RT-15：区域样式复用现有 effect 注入模式，只有一个指定 id 的 style，清空及卸载时清理。
- RT-16：仅改变字体也调整标签栏行高与高度；40 px 下行盒随字号变化，不保留固定 16 px 行高。
- RT-17：字体加载回调在卸载或旧实例上不刷新；父组件传入等值新主题对象不导致重复重绘。

## 架构复审验收（2026-10-05）

- RT-18：store 保持原有扁平初始化结构；同步只维护模块级在途请求和单调快照时间。
- RT-19：config 广播携带安全完整配置，复用 hydrate 同步所有字段；主题、终端主题、语言与 CSS 均实时生效。
- RT-20：旧 updatedAt 快照不覆盖新值；配置广播无需再 GET，连接恢复和可见性恢复使用通用 syncConfig。
- RT-21：区域样式只注入 :root CSS 变量；组件通过稳定区域类消费变量，无标签允许列表或 !important；用户 CSS 可覆盖。
- RT-22：两种标签栏保留各自 30/36 px 最小高度，错误及加载状态也消费区域变量；高度随文字自然增大。
- RT-23：useTerminal 仅由 props 驱动；工作区与移动端组合点显式解析覆盖，登录安装终端不受全局区域设置影响。

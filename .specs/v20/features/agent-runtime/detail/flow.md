# Agent 启动、环境配置与会话绑定恢复：使用流程

## 基本流程

1. 保存启动环境配置。
2. 启动或恢复 Agent，launcher 读取参数和环境。
3. 识别进程、hook 与 runtime snapshot，恢复根会话和就绪状态。

## 异常与约束

- 环境变量只作用于新启动进程，不追改运行中的进程环境。
- review 子会话与根会话身份需区分，不能因子会话 hook 切换面板绑定。

具体实现与测试入口见[规格](../spec.md)。

## 按代理配置流程

1. 加载配置，缺失的代理字段初始化为空对象。
2. 编辑任一代理，校验后仅 PATCH 对应字段；服务端确认后更新已保存状态，避免把失败配置当成已生效。
3. Claude 所有启动入口共用 Node 包装器，执行时读取 config.json，仅将 claudeEnvironment 合并到子进程 env；命令不携带变量值。Codex 保持现有启动器。
4. 恢复已有会话时也读取最新配置；运行中的进程保持原环境。AI 文本调用按 provider 读取配置，显式调用参数优先。
5. 非法配置阻止启动；缺失配置文件视为空配置，其他读取错误明确失败。两种代理配置相互独立。

## Review 修复：shell 包装与环境优先级

- Claude 运行检测及会话绑定共用有界后代 PID 遍历；复用已加载的直接子进程，去重并排除 pane 根 PID，覆盖多层 shell、Node 包装器及非 exec 函数。
- 回退登录 shell 完成初始化后，从独立 fd 3 管道读取并应用对应代理配置，再调用 Claude。POSIX shell 与 fish 分别生成字面量赋值；命令行不包含变量值，标准输入继续提供给终端。

## 启动参数边界

前后端均以参数数组构建 Claude 启动/恢复命令；进入外层 shell 时逐项转义。启动器在 Node 内展开 settings 和 prompt 路径的 ~/ 前缀，随后直接 spawn Claude。仅函数/别名回退需要 shell，并按 POSIX/fish 的明确字面量规则转义，保证美元符号、反引号、反斜杠、引号和换行仍是参数内容。

相同环境内容保存时，store 比较键集合与字符串值（忽略键顺序），直接完成，不触发 PATCH、磁盘写入或同步广播。编辑器原有禁用无改动保存按钮的行为保留。

后代遍历限制 16 层、1024 个候选，每批最多 16 个并发子进程查询。fd 3 内容必须完整且应用成功，fd 4 确认后才视为回退启动就绪；空流、截断、失败赋值或读取错误不允许继续启动 Claude。

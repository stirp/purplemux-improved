# Fork 后累计新增与增强需求

## 需求来源

用户明确要求：“我们应该将 fork 以后的所有新增功能都写到 v20 版里”。v20 因此汇总 fork 后全部功能增量，应用版本号单独记录为元数据。

## 基线与截止点

- 基线：`52140216d8bb5bfffed30d8d452f77b88339a4ae`，由仓库 [README](../../../README.md) 和[中文 README](../../../README.zh-CN.md)明确标注。
- 截止：`3637a357012b7f27331b65cf793061c9af8e11d8`，本次扫描时的 HEAD。
- 范围：`52140216..3637a357` 的 48 个非合并提交，以及它们在当前源码中的最终行为。
- 应用版本：`0.5.1`；规格阶段：`v20`。两个编号用途不同。

## 需求目标

- 汇总所有新增功能、用户可见增强及支撑这些功能的修复，不能只抄 README 摘要或提交标题。
- 延续 `.specs/vN/PRD.md`、`task.md`、`features/<name>/spec.md` 和详情文档结构。
- 每个功能关联当前源码、已有测试与提交，支持追溯和后续维护。
- 同一功能的多次修复合并描述最终行为；上游已具备的基础功能不冒充 fork 新增。
- v1 至 v19 保留原样；v20 作为 fork 增量总规格。

## 覆盖方法

以 [提交覆盖表](./commit-coverage.md) 为完整性检查入口，以各功能源码和测试索引校验最终行为。合并提交不重复计为功能，普通版本和兼容性改动纳入平台模块。

## 不属于本次执行的操作

文档描述的提交、推送、删除、同步等是产品能力，并非本次执行授权。本次仅回补规格，不执行这些业务操作或发布。

# 同步与交付：无目标时默认当前分支

- 日期：2026-09-29
- 状态：已实现，自动化回归通过；实机验收未执行
- 优先级：P2
- 关联规格：[Worktree 同步与 PR/MR 草稿交付](../features/worktree-sync-delivery/spec.md)

## 原始需求

> 如果打开“同步与交付”的时候没有目标分支，则默认目标分支是这个分支自己。

## 目标与范围

用户从桌面或移动端打开某个工作树的“同步与交付”时，如果现有规则未能选出目标，则自动选择该工作树当前检出的本地分支，减少手动选择。这里的“当前分支”属于弹窗所对应的工作树，而非父工作区或仓库主工作树。

仅调整同步目标默认值、候选展示和同分支比较状态，不改变 PR/MR 草稿的目标分支规则。

## 行为规则

1. 保留用户在弹窗中显式选择的目标；默认值优先采用仍有效的 `metadata.targetRef`，其次采用仍有效的 `metadata.baseRef`。
2. 两项元数据均不能提供有效目标时，使用当前工作树的 `refs/heads/<branch>`。不推断为 `main`、`master`、上游或同名远程分支。
3. 当前本地分支应出现在候选中，默认显示值、勾选状态与服务端返回的 `targetRef` 一致；用户仍可切换到其他目标。
4. 默认自身时，`targetHead` 对应当前分支提交，正常稳定状态下 ahead/behind 均为 0。merge/rebase 置为不可用，服务端继续拒绝同分支同步；这不影响独立的推送和交付流程。
5. 无当前命名分支（detached HEAD）或无可解析提交时，不伪造目标，保留现有空状态、错误与操作限制。
6. 默认解析发生在首次读取及后续无显式目标的刷新中，不因刷新覆盖用户已选目标。用户显式请求无效目标时保留错误，不静默切换为自身。
7. 打开弹窗只读取本地状态，不写入目标元数据，不自动执行 fetch、merge、rebase 或 push。

## 验收标准

| 场景 | 预期结果 |
| --- | --- |
| 无保存目标、无创建基线，当前分支为 `feature/example` | 默认选中 `refs/heads/feature/example`，列表勾选一致，ahead/behind 为 0 |
| 保存目标有效 | 保留保存目标，不回退到自身 |
| 保存目标失效，但创建基线有效 | 使用有效创建基线 |
| 保存目标和创建基线均失效，当前分支有效 | 回退到当前本地分支 |
| 仓库只有当前一个本地分支且无远程 | 仍能默认选中自身并展示比较结果 |
| 从父工作区打开子工作树弹窗 | 使用子工作树的当前分支 |
| 用户切换其他目标后刷新 | 保留选择并展示对应比较结果 |
| 用户显式请求不存在的目标 | 显示错误，不静默回退 |
| detached HEAD 且无有效默认目标 | 保持未选择及现有限制 |
| 默认目标为自身 | merge/rebase 不可用；直接调用同分支同步仍被拒绝 |
| 桌面与移动端打开同一工作树 | 默认行为一致；仅打开弹窗不会写元数据或触发 Git 写操作 |

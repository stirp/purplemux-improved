- 使用 `npm version patch --no-git-tag-version` 更新应用版本，不创建 Git 提交或标签。

- 性能改动应保持现有交互、配置和数据兼容，不以性能优化名义增加无需求依据的功能。
- 本版按测量结果分轮实施；版本准备和局部优化不代表全部工作完成或已打包发布。

## 基线场景与执行顺序

1. 准备脱敏或合成数据，不读取或改写用户真实会话作为压力测试样本。
2. 使用相同生产构建，在 1、10、30 标签下分别测量空闲、单个 Agent 活跃及多个 Agent 活跃；覆盖浏览器前后台和多客户端。
3. 会话目录准备 50、500、2000 个历史会话；长会话准备 1、10、100 MiB JSONL，分别测量首次打开、热缓存、30 秒后刷新和实时追加。容量是测试负载，不是产品限制。
4. 记录数据集、运行次数、预热方式及原始结果；相同条件前后对比。耗时指标使用足够样本计算 p50/p95，并记录波动。
5. 优先推进 PERF-02、PERF-03、PERF-04 中测得收益最高的项目，同时开展 PERF-05 稳定性验证。PERF-06、PERF-07 依据结果纳入本版或后续版本。
6. 每项编码前补齐对应功能 spec 和适用的 ui/flow/api 行为；完成相关测试、完整 TypeScript、改动文件 ESLint，以及影响范围内的生产构建和浏览器/实机验证。

## 本版完成条件

- 基线和优化后的结果可重复，实际优化项有数据证明收益，未优化场景无显著退化。
- 新增缓存、合并和调度策略有明确失效、资源上限及恢复约定，不通过丢消息或隐藏错误降低开销。

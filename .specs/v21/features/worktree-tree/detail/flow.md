# 流程

打开时读取项目仓库工作树，并按 parentWorkspaceId 建树。对每条边用子分支与父本地分支比较 ahead/behind。选择合并方向后检查目标工作树状态和目标 HEAD，显式确认执行 merge，刷新结果；冲突后可进入已有同步弹窗处理。失效或跨仓库关系标记为不可用。

父工作区包含多个仓库时，先定位子工作树所属仓库，再只在该仓库内匹配父工作树；不能因为父工作区的首个仓库不同而判定关系不可用。同仓库找不到父工作树时仍标记不可用，不回退到其他仓库。

加载错误与合并操作错误分别保存。自动或手动刷新成功只清除加载错误，不能覆盖合并失败原因或主工作树冲突后的终端恢复提示；刷新失败时两类错误均可见。上一次合并错误在下一次确认执行合并或关闭弹窗后清除。

仓库视图接管新 worktree 后关闭当前入口并打开接管的工作区；删除后刷新仓库视图和关系视图。安全删除、批量预览、交付等操作仍遵循既有确认和状态校验流程。切换视图不会重置仓库搜索或已选择的清理候选。

AI 提交成功后按会话所属工作区和实际提交的仓库目录查找工作树，确认 HEAD 仍等于提交结果才读取交付信息；找不到匹配项或状态变化时仅提示从 Worktree 管理继续。推送与草稿分别确认，不自动运行；提交状态不明时不显示交付表单。交付过程繁忙时不可关闭弹窗。

审查修正：父向子合并在子工作树执行 `git merge <父分支>`，子向父合并在父工作树执行 `git merge <子分支>`；确认文案分别显示合入来源和受修改的目标。主工作树的合并若发生冲突，需在终端完成或中止；非主工作树继续使用已有弹窗恢复入口。

变更面板打开弹窗时固定当前目录、分支、HEAD。初始 inspect 返回 noChanges 时，使用此快照进入交付；提交执行返回 noChanges 或 commitUnknown 等失败时不能转入交付。工作树列表及 inspectSync 两次读取都复核分支和 HEAD，身份变化则停止发布并提示重新进入。成功提交后使用实际提交结果的 HEAD。推送与草稿仍分别确认，提交不会自动触发后续写操作。

# 项目 Worktree 父子关系与同步

项目根工作区存在子 worktree 时，在根节点显示关系与同步入口。界面按配置的 parentWorkspaceId 绘制完整树，逐条展示子分支相对父分支的未合入提交数及父分支尚未同步的提交数。在同一界面分别将子合并到父，或将父合并到子；操作必须显式确认、重新校验快照，失败显示原因及冲突恢复入口。无子 worktree 时不显示关系视图；缺失目录、分支或不同仓库时显示不可用状态。桌面和移动端一致。

## 根入口与导航层级（2026-10-14）

- 项目根工作区行外露 Worktree 管理按钮，与齿轮并列；无子节点也可进入仓库视图发现工作树。沿用工作区目录作为仓库发现范围，非 Git 目录沿用管理弹窗空状态。子节点保留菜单入口。
- 父子层级使用连续竖线、末项折线及目录/分支图标，显示直接子项数量及工作树分支，去掉重复的“父名称 / 子名称”行。深层、兄弟、折叠、缺失父项均须可读。
- 桌面齿轮仅在项目行 hover、键盘 focus-within 或菜单打开时显示，隐藏时不占布局宽度；根管理按钮始终可见。按钮不触发选择、折叠、重命名或拖动。
- 触摸布局隐藏齿轮；项目长按 350ms 后移动超过 8px 开始拖动，保持不动 650ms 打开菜单，之后本次触摸不再拖动。350ms 前移动交给滚动，短按选择项目；取消、多指及卸载清理手势，长按结束不产生点击穿透。Tab 维持原行为。
- 桌面右键、键盘菜单键和移动长按均可到达全部项目操作。触摸仿真通过不等同于 iOS/Android 实机验收。

## 管理入口整合

当根工作区有子 worktree 时，原“管理 Worktrees”与关系树合为一个入口、一个弹窗，通过“关系与同步 / 仓库 Worktrees”视图切换。仓库视图完整保留旧版检索、过滤、打开/接管、空间统计、状态、交付、安全删除和批量清理；未纳入父子工作区的磁盘 worktree 仍可发现与接管。无子 worktree 和非根工作区进入统一管理弹窗的仓库视图，避免失去接入能力。创建 worktree 的独立入口保持原行为。切换视图不能丢失已输入的筛选及选择状态；删除或接管后重新获取关系。移动端与桌面保持一致。

## 统一交付入口与提交后操作

移除桌面及移动工作区行最右侧单独的“同步与交付”图标。每个工作区保留一个 Worktree 管理菜单入口：有子工作区时显示关系与同步视图；无子工作区时只显示仓库 Worktrees 管理视图，确保仍可发现和接管未关联的工作树。仓库视图保留逐条工作树的交付入口。

在 AI 生成提交信息的弹窗内，本地提交成功后根据实际提交目录查找对应的已管理工作树，展示现有的推送分支与创建 PR/MR 草稿流程；均需要各自显式确认，提交成功本身不自动推送或创建草稿。未匹配到受管工作树或无远端时保留提交结果并提示无法继续交付。提交结果不明确时不触发推送。桌面与移动端共用该交互。

## 变更面板快捷入口

在桌面 Git 侧栏和移动 Git 全屏的顶部工具栏保留明确可见的“提交与发布”按钮，Changes/History 两个视图均可使用。点击后打开共享提交发布弹窗，支持 AI 生成或手写提交信息、本地提交、推送及发起 PR/MR 草稿。无待提交改动时，允许直接继续发布已有提交，不强迫用户先创建新提交。非 Git 目录、detached HEAD 或正在同步时不可发起。窄屏工具栏允许换行，不能挤出刷新和关闭按钮。

发布已有提交时使用打开快捷入口时展示的仓库、分支、HEAD；读取工作树及同步状态后均须复核身份。变化时提示重新打开，不自动改用其他分支或新 HEAD。每项写操作仍需用户明确触发；提交响应不明时不开放发布操作。

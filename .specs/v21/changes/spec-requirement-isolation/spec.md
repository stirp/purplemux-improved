# 按需求隔离规格文档

## 用户需求与范围

用户要求修改现有规范，避免多个需求都修改同一个 Markdown 文件，导致合并冲突。
当前规范要求每个需求同步版本级 PRD 和任务表；本次改为按需求独立维护规格、任务与证据。
仅调整文档规范及当前版本入口，不修改应用代码，不迁移历史规格。

## 行为约定

- 新需求使用 `.specs/v{N}/changes/<requirement-id>/`，需求 ID 使用有业务含义的小写连字符名称，不使用需要集中分配的连续编号。
- 每个目录独立保存规格、任务和实施/验证记录；原始需求可写在规格中，较长时拆到目录内的 `requirement.md`。
- 版本 PRD、版本任务表、AGENTS 和共享功能规格不再作为每个需求的登记点；通过文件搜索发现新需求。
- 已有功能的新增需求使用独立增量规格，通过 `depends_on` 引用基线及前置变更，注明覆盖条款；同一条款发生不兼容变更时必须协调，不按文件名或日期自动覆盖。
- 旧路径和历史证据保留；已有需求的未完成工作可继续维护原有需求专属文件，进度改用独立任务文件。版本汇总仅在明确的汇总整理任务中更新。

## 验收标准

1. 规范不再要求新需求修改版本 PRD、版本任务表或其他集中登记文件。
2. 任意两个不同需求 ID 的文档路径互不重叠，无需先登记到共享索引。
3. 新需求及其进度可以通过明确的搜索命令发现；旧文档及链接仍有效。
4. 已有功能的行为变更仍要求先写规格，且明确基线引用、覆盖关系和语义冲突处理。
5. 本次文档检查、实际结果及未执行项记录在本目录中。

见[任务](./task.md)及[实施与验证记录](./result.md)。

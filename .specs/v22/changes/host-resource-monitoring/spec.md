# 服务器 CPU 与内存监控

## 用户原始需求

“由于同时可能有多个 Codex 和 Claude 进程在争抢 CPU 和内存，所以我需要在界面增加一个 CPU 和内存的监控。它在移动端的位置需要仔细设计。”

## 范围与覆盖关系

- 现有源码中的 SystemResources 仅支持 Electron 应用自身的资源用量，默认关闭，没有独立功能规格；本段记录现状，不宣称此前按规格实现。
- 替代该组件的数据口径，统一使用服务端所在机器整机 CPU/内存，覆盖浏览器、Electron、移动端。不是手机资源，也不是单个 Agent 的资源排名。
- 保留已有 systemResourcesEnabled 配置键和明确的 false；缺失时默认开启，设置入口开放给所有客户端。不迁移或主动覆写已保存配置。
- 增补移动顶栏资源入口，不改变导航抽屉、工作区/Tab 切换及底部输入区域。沿用前置规格其他条款。
- 不增加进程控制、历史图表、告警通知、后台长期采集或新依赖。

## 行为约定

- CPU 使用 Node OS 各逻辑核累计时间的差值，归一化为整机 0–100%。首次及采样间隔超过 15 秒显示采样中，不以开机累计值冒充即时用量。
- 内存显示已用比例和已用/总量，Linux 使用 MemAvailable（含可回收缓存）；无法读取时回退 OS 空闲内存口径并在详情说明。其他平台使用 OS 空闲内存口径。
- 服务端按需采样，2 秒内复用快照与并发请求；无常驻采样定时器。不扫描进程，不调用 tmux；原有 tmux 数量不再混入资源指标。
- GET /api/system/resources 返回 sampledAt、cpu（百分比或 null）、memory（used/total/available 字节及 basis）；沿用 proxy 鉴权，no-store，其他方法 405，采样失败 503。
- 客户端单次请求结束后间隔 3 秒刷新，5 秒超时，禁止重叠；关闭监控、卸载、页面隐藏时取消请求和定时器，回到前台立即刷新；失败清除展示数值并自动重试，不保留伪实时数据。
- CPU/内存达到 80% 显示偏高、90% 显示高，使用主题警示色；详情同时给出文字，不依赖颜色。

## 界面约定

- 桌面：复用内容顶栏左侧位置，CPU/内存百分比横排，点击打开详情浮层。
- 移动：保持现有 48px 顶栏高度，右侧退出按钮前放两行 CPU/内存百分比按钮，至少 44px 热区。品牌缩为图标，360px 以下隐藏品牌图标及分隔符，优先保留工作区名；长名称省略，资源区不收缩。无工作区时保留可缩略品牌名称。
- 移动详情使用底部 Sheet，展示“服务器资源”、整机口径、百分比、内存已用/总量及采样时间。内容可滚动，关闭按钮至少 44px，适配底部安全区，Escape/遮罩关闭并归还焦点。
- 初始、失败及恢复均保持入口尺寸稳定；正常情况下不弹 toast，不打断聊天。
- 沿用浅深色主题、本地化和已有配置保存逻辑。

## 验收标准

1. 多核 CPU 差值、首采样、长间隔、内存口径及失败降级有测试；服务端不对每个客户端重复昂贵采样。
2. API 方法限制、缓存头和失败行为通过测试；沿用鉴权匹配范围。
3. 默认缺失开启、明确 false 保留；关闭/后台/卸载无持续请求，超时和断网后可恢复，Electron 使用同一服务端接口。
4. 桌面入口和移动底部详情可打开关闭，指标更新、加载/错误提示及告警文字正确。
5. 320/390/430px、横屏短屏、桌面、浅深色及放大文字无横向溢出；移动新增热区至少 44px，长工作区名不挤掉指标，详情内容和关闭可达。
6. 相关单测、完整 TypeScript 和改动文件 ESLint 通过；浏览器验证及未执行的实机检查如实记录。

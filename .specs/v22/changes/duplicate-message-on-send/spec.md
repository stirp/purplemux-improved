# 防止发送后重复显示与队列未确认

## 原始需求与现场

用户反馈“发送后同一句话出现了两次”。截图中待确认气泡以“严重”开头，原生记录以“确定严重”开头；补充截图显示队列仍保留原文并提示未确认。用户明确仅使用 Web 输入框，没有在 Terminal 留草稿。

现有源码允许向带文字的 Codex 输入框继续粘贴。正文被拼接时，服务端和客户端的严格回执匹配均失败。截图中额外前缀的来源尚未复现，不将其归因于用户手动输入。

## 范围与覆盖关系

- 增补前置规格的投递就绪条件：Codex 普通队列投递必须确认输入框为空；随机占位提示不算草稿，实际文字、粘贴折叠标记、附件或多行内容不能当作空输入框。
- 保留原文和附件，检测到残留时不粘贴、不按 Enter、不清空终端，返回明确错误，用户处理终端内容后可重试。无法确认输入区时沿用 terminalNotReady。
- 保留原有会话身份、尝试时间、正文及图片身份匹配。带额外前缀的记录不能仅因包含原文而自动确认为成功；不以隐藏占位、空队列或忙碌状态掩盖投递差异。
- 不改变 Claude 投递、原生命令、立即问题回答及配置存储；桌面和移动端复用队列错误提示。
- 已经发生的拼接不自动重发、不自动删除历史或取消运行中队列；本次现场缺少对应原生日志，记录这一限制。

## 验收

1. 普通空输入框及带暗色占位提示的空输入框仍能发送。
2. 输入框有“确定”、粘贴占位、附件或多行文本时保留队列，明确报错；无粘贴、Enter 或清空操作，后续消息不自动发送。
3. 终端恢复为空后显式重试正常发送；重试前先检查迟到回执，已收到时不再次写入。
4. 输入框读取失败、界面禁用或弹窗仍不能发送；保留旧同文、不同附件及会话切换回归。
5. 带额外前缀的原生记录不被模糊匹配吞掉；记录与尝试元数据乱序、重连及正常回执仍只保留一个已确认气泡。
6. 执行相关单元测试、完整 TypeScript、改动文件 ESLint 及构建；区分可控复现与真实截图现场，记录未验证项。

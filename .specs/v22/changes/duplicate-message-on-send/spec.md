# 防止发送后重复显示与队列未确认

## 原始需求与现场

用户反馈“发送后同一句话出现了两次”。截图中待确认气泡以“严重”开头，原生记录以“确定严重”开头；补充截图显示队列仍保留原文并提示未确认。用户明确仅使用 Web 输入框，没有在 Terminal 留草稿。

现有源码允许向带文字的 Codex 输入框继续粘贴。正文被拼接时，服务端和客户端的严格回执匹配均失败。截图中额外前缀的来源尚未复现，不将其归因于用户手动输入。

后续用户定位：“在 web 有时候虽然是在发消息的输入框输入，但是结果不知道为什么进入了 tui 的输入框里，此时界面上并没有展开 terminal 的部分，都是 chat 的部分。”本轮继续修复隐藏终端抢焦点与接收输入的上游路径。

PR #88 审查补充：草稿以空行开头、正文位于后续行且光标回到起点时，仅检查提示符和下一行会误判为空。见[审查意见](https://github.com/stirp/purplemux-improved/pull/88#discussion_r4367095297)。

## 范围与覆盖关系

- 增补前置规格的投递就绪条件：Codex 普通队列投递必须确认输入框为空；随机占位提示不算草稿，实际文字、粘贴折叠标记、附件或多行内容不能当作空输入框。
- 保留原文和附件，检测到残留时不粘贴、不按 Enter、不清空终端，返回明确错误，用户处理终端内容后可重试。无法确认输入区时沿用 terminalNotReady。
- 保留原有会话身份、尝试时间、正文及图片身份匹配。带额外前缀的记录不能仅因包含原文而自动确认为成功；不以隐藏占位、空队列或忙碌状态掩盖投递差异。
- 不改变 Claude 投递、原生命令、立即问题回答及配置存储；桌面和移动端复用队列错误提示。
- 已经发生的拼接不自动重发、不自动删除历史或取消运行中队列；本次现场缺少对应原生日志，记录这一限制。
- 新增隐藏终端输入边界：桌面 Chat 收起 Terminal、非终端页面及移动 Chat 后台终端不参与 Tab 顺序、不接受自动或延迟聚焦，也不把键盘、粘贴、输入法尾事件发送到 PTY。后台终端继续挂载、解析输出、同步标题和尺寸；Web 提交、停止、信任提示等显式发送通道保留。
- 终端连接/重连不得夺走 Web 输入框、弹窗或其他已聚焦控件的焦点。收起已聚焦终端必须释放其焦点；仅明确展开或进入可见原生菜单后允许终端交互。
- `/` 与 Codex `$` 仍按原生菜单规格主动展开终端后交接焦点；关闭或切换后，旧延迟回调不得聚焦隐藏终端。此前“原生命令不变”指触发及发送语义不变，本轮补充可见性前提。
- 输入区检查覆盖提示符至底部状态区分隔行之间的完整区域；不能将草稿中的第一个空行当作结束。按现有 Codex 布局，从底部连续状态区向上定位分隔行，忽略屏幕末尾填充空行；额外输入行（包括空行）不算空输入框。不依赖模型名或自定义状态行正文，无法确认就绪时仍保留队列。

## 验收

1. 普通空输入框及带暗色占位提示的空输入框仍能发送。
2. 输入框有“确定”、粘贴占位、附件或多行文本时保留队列，明确报错；无粘贴、Enter 或清空操作，后续消息不自动发送。
3. 终端恢复为空后显式重试正常发送；重试前先检查迟到回执，已收到时不再次写入。
4. 输入框读取失败、界面禁用或弹窗仍不能发送；保留旧同文、不同附件及会话切换回归。
5. 带额外前缀的原生记录不被模糊匹配吞掉；记录与尝试元数据乱序、重连及正常回执仍只保留一个已确认气泡。
6. 执行相关单元测试、完整 TypeScript、改动文件 ESLint 及构建；区分可控复现与真实截图现场，记录未验证项。
7. 在 Chat Web 输入框编辑期间模拟终端首次连接、重连、延迟 focus：Web 焦点和草稿保持，隐藏终端不收到文字；覆盖桌面折叠和移动透明后台终端。
8. 隐藏前已聚焦终端时释放焦点，隐藏期间键盘、IME、粘贴和迟到 onData 不投递；输出、标题及 Web 显式发送不因隐藏而断开。
9. 普通可见终端恢复键盘输入；显式 `/`、`$` 原生菜单可见后正常聚焦与输入，关闭/切换后的延迟调用不能抢回隐藏终端。浏览器实测真实 xterm 的焦点、Tab 导航与中文输入，记录实机 IME 限制。
10. PR #88：`› \n\n  existing draft\n\n  GPT-6 · Full Access\n  ? for shortcuts` 且光标为 `{ x: 2, y: 0 }` 必须判为已有草稿；覆盖多个前置空行、空白行、正文后的空行、暗色附件及底部填充。正常空输入框和多行自定义状态区保持可发送；队列遇到此类草稿保留原文和附件，不粘贴、不按 Enter、不自动发送后续消息，清空后显式重试恢复。

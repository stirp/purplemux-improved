# 工具结果可读展示与原文回退

## 用户原始需求

> tool-reulst渲染优化, 现在显示的都是原始 json 结构，可读性不高。对不认识的结果可以原样显示

2026-10-20 补充需求：确认 Claude 仅接入共享组件、尚未传递完整结果后，用户要求“那么支持一下”，补齐 Claude 解析到展示链路。

## 范围与基线变更

- 改善共享时间线 `ToolCallItem` 已有 `output`（缺失时为 `summary`）的展示，覆盖桌面、移动端与子 Agent 中复用的工具组。
- 将 v8 工具结果仅展示摘要、v19 工具结果纯文本展示条款增量替换为：识别已知结果包装并展示正文，未知结果原文回退。当前源码已经提供 Codex 完整 output；此事实不是本需求新增的解析能力。
- Claude 解析器新增完整 `output`，替代 v8 session-parser 中结果仅保留摘要的条款；通过可选的 outputFormat/outputTruncated 传递原文类型与预览省略状态，旧条目缺省时保留既有识别。修正 WebSocket 背压与展示缓存的大结果边界；历史分页游标、原始日志存储和工具调用状态逻辑不变；仅有摘要的旧缓存仍显示摘要，从原始 JSONL 重新解析后提供完整结果。不修改工具输入、diff、终端和独立流式事件适配规则。

## 行为约定

1. 命令结果：识别字符串 `output` 或 `stdout`/`stderr`，且含有效 `exit_code`、`wall_time_seconds` 或 `session_id` 的对象。正文按等宽文本保留空白；退出码、耗时、运行会话单独显示；stderr 与非零退出码突出错误。
2. MCP/内容块：识别 `{ content: [...] }` 或内容块数组中的 `text`/`input_text` 文本块，正文支持安全 Markdown（段落、列表、表格、代码）。以方括号链接（含数字标签、引用式链接或链接定义）开头时，不得仅凭 `[` 将全文降级为原文；有效 JSON 仍优先作为 JSON 处理，未知、畸形或截断 JSON 继续原文回退。混合内容中的未知块以 JSON 展示，不丢弃；未知附加字段可从完整原文查看。`isError: true` 保持可见错误提示。
3. 支持文本块内嵌的已知 JSON 包装与 `Promise.allSettled` 的 fulfilled/value 包装；仅在内部确实识别时解包，不根据任意 `message`/`data` 字段猜测语义。
4. 未知 JSON、普通文本、畸形或截断 JSON、空数组、全未知内容块保持原始字符串，包括空白和换行。识别深度最多 5 层，超过 200,000 字符不解析，退回原文；识别器不另行截断；Claude 进入协议前采用第 12 条资源边界。
5. 已识别结果默认显示可读内容，并提供可展开的“原始结果”，逐字保留传入的正文或预览字符串；仅在展开时挂载原文 DOM，收起后释放。该折叠状态仅在当前组件内，不新增设置或保存请求；重连后使用最新 props 重新计算结果。
6. 不执行 HTML，不自动加载结果中的图片或其他媒体。沿用主题语义色；长内容限制高度并滚动，长单词换行，表格及代码块在容器内滚动。新增标签覆盖现有全部语言。
7. MCP 包装对象中的 `isError: true` 不依赖内容识别成功：空 `content`、全未知块或无效文本块也显示错误提示，并保留原文；外层工具结果 `isError: false` 不覆盖包装中的错误。嵌套内容及 fulfilled 包装同样传递错误，后续正常结果清除旧错误提示。
8. 简写引用链接 `[report]` 开头时，检查后续匹配的链接定义再决定 Markdown 展示；标签匹配忽略大小写并折叠空白，支持转义方括号及换行。缺少定义、标签不匹配或仅有空定义时仍原文回退，有效 JSON 的优先级不变。
9. Claude 的 `tool_result.content` 写入 `ITimelineToolResult.output`：边界内字符串逐字保留；数组和其他 JSON 值按第 12 条序列化，保留边界内文本块、未知块及块顺序，不再只取首个文本块。缺失内容时 `output` 缺省，空字符串不制造额外正文，`null`、数字和布尔等已存在的 JSON 值不丢弃。未知媒体保留 JSON，不自动加载。
10. Claude 字符串日志/文件内容显式标记为 text，绕过 JSON 形状识别，即使字符串是合法命令/MCP JSON 也保持等宽原文，结构化文本块复用 Markdown、嵌套 JSON 识别及原文入口；`is_error` 保持决定调用状态和错误样式，同时错误正文按第 12 条预览边界可见。Edit/Write 成功时继续以原有 diff 展示，失败时显示错误正文。
11. 保留现有 `summary` 及 `toolUseResult.answers` 优先级，确保 Bash 行数、Grep/Glob 计数、AskUserQuestion 回答、TaskCreate 任务编号、计划状态不因传递完整正文改变。初始解析、历史按轮读取、增量追加、子 Agent 结果复用同一输出规则。
12. Claude 单项 output 最多 65,536 个 UTF-16 单元（不拆分代理对），超出时仅传前缀预览；结构化内容遍历最多 32 层、2,048 个节点。超界分支显示省略标记，不递归序列化原始深层对象；图片/音频/文档的 base64 data 与资源 blob 用省略标记替代，保留类型、媒体类型及其余小字段。任何省略设置 outputTruncated 并显示本地化说明，原始数据仍在 JSONL 中。若序列化后超界，前缀标记为 text 防止残缺 JSON 被再识别。此条替代“任意大小结果完整进入 UI”的约定，适用于当前需求新增的 Claude output。
13. WebSocket 按连接有序排队；bufferedAmount 达 1 MiB 时暂停发送，50ms 后重试，不依赖下一次文件更新。待发送队列最多 4 MiB/256 条（未拥塞时单条大 init 可直接发送），持续背压 10 秒或发送失败则明确关闭连接，由既有重连 init 恢复；不得推进读取后静默丢弃消息。关闭或切换订阅时释放待发送旧数据，不影响其他连接。
14. 展示缓存继续最多 12 会话、2 MiB/项、5 分钟 TTL。替换 v20 PERF-OPEN-04 的整轮同步 JSON 字符串估算为保守大小估算与不可变对象的 WeakMap 复用；大轮次先移除工具正文、保留摘要和状态，仍超界则保留可容纳的最新条目。缓存为恢复前预览，不能恢复分页游标；不得因工具正文大而静默清空原快照。无需序列化整轮或复制大字符串来计量。
15. Claude 回扫只判定用户消息边界，不生成工具结果；复用用户消息的协议过滤语义。对跨多个 64 KiB 块的工具结果（含 UTF-8、多文本、媒体、深层 JSON）、不完整末行及增量补全验证字节游标与内容顺序。缺失 content 的服务端对象必须没有自有 output 属性，传输前后契约一致。
16. 恢复会话已定位到 JSONL 且当前仍订阅旧文件时，必须先取消旧订阅并清理旧队列，再发送 timeline:resume-started，最后初始化新订阅。背压消退后，恢复确认必须先于新会话 init 到达且仅到达一次；清理旧数据不得删除恢复确认，避免桌面/移动面板的恢复加载状态无法结束。未定位到文件、恢复被阻止或失败的既有分支不变。

## 验收标准

| 编号 | 验收条件 | 验证方式 |
| --- | --- | --- |
| TR-01 | 命令正文不再展示 JSON 包装，退出码 0、非零、耗时 0、运行会话、空输出及 stderr 正确 | 识别与组件测试 |
| TR-02 | MCP Markdown（含方括号链接开头及后续标题、列表、表格）、嵌套命令及混合未知块可读且不丢内容 | 识别与组件测试 |
| TR-03 | 识别器对未知、畸形、超限、错误类型及纯文本逐字回退，原文入口可查看完整传入正文/预览 | 边界与交互测试 |
| TR-04 | 错误可见、纯摘要兼容、原有 diff 隐藏成功结果的行为保留，实时更新不显示旧正文 | 集成测试 |
| TR-05 | HTML 不执行，媒体不自动加载，窄屏可换行/滚动；本地化键齐全 | 组件测试、构建、样式检查 |
| TR-06 | 相关测试、完整 TypeScript、改动文件 ESLint 通过，实际验证限制有记录 | 验证记录 |
| TR-07 | Claude 边界内完整字符串、多文本块、未知块及错误详情经 JSONL 解析、序列化传输后正确展示，超限正文有界预览并明确提示 | 解析与组件集成测试 |
| TR-08 | Claude 摘要、回答、任务编号、计划状态及 diff 保持兼容，初始/历史/增量/子 Agent 均遵循同一输出边界 | 解析、分页与组件回归 |
| TR-09 | JSON 形状的 Claude 字符串不被重新解释；缺失属性严格缺省；深层内容不使初始/历史/增量失败 | 解析及组件回归 |
| TR-10 | MB 级媒体、超长文本、超多节点受限且省略可见；折叠原文不常驻 DOM；大轮次缓存仍有可用摘要 | 资源边界、缓存及浏览器验证 |
| TR-11 | 背压恢复后无需文件新变更即可有序补发；超时/队列满主动重连；关闭/订阅切换清理；跨 64KiB 回扫不截断或乱序 | 发送器与服务端、分页集成测试 |
| TR-12 | 从旧订阅恢复到已有 JSONL 时，有/无背压均依次收到一次恢复确认和新 init，旧订阅的排队数据不泄漏 | 服务端恢复与背压集成测试 |

见[任务](./task.md)与[实施及验证记录](./result.md)。

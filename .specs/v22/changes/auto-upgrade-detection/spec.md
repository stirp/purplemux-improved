# 自动检测更新与一键升级重启

## 用户需求与范围

用户要求：“需要支持自动升级的检测，并且可以一键升级重启”，并确认 Electron 桌面版和浏览器/CLI 服务端两种方式都支持。工作区名称补充“需防止任务中断”。

## 行为约定

- 启动后自动检查，运行期间每六小时检查；检查失败保留当前版本并允许重试。仅检测稳定版，不自动下载、安装或重启。
- 系统设置显示当前版本、新版本、检测/下载/重启状态及错误。发现更新时工作区显示持续可见的更新入口；移动端可操作。
- 浏览器升级其连接的服务端；Electron 升级本机桌面客户端。桌面远程连接不升级远程服务，远程服务由浏览器入口管理。
- 点击“升级并重启”授权本次版本的下载、安装与重启，无第二次正常确认。下载失败不退出；忙碌或无法确定状态时阻止操作，提示稍后重试；下载完成后必须再次检查会话状态。不会等到未来某时刻偷偷重启。
- 接受安装操作后，在首次异步空闲检查前同步进入 `checking` 忙碌状态，使 HTTP/IPC 的即时响应禁用操作按钮并启用快速轮询。若已有版本检测正在运行，用户的安装请求等待该次检测结束后使用最新检测结果执行；重复安装请求合并，检测失败或已无新版时不安装。该等待仅针对在途版本检测，不等待会话未来变为空闲；空闲检查阻断后仍须用户重新点击。
- 复用严格 tmux 快照与 StatusManager 空闲判定，busy、needs-input、unknown、压缩/权限等待、普通终端运行任务、额外 pane 和未知会话均阻止重启。退出仅断开 PTY，保留 tmux 会话与工作区数据。最终检查与退出之间无法锁定用户在外部终端的新输入，不承诺原子冻结任务。
- npm 服务端由启动器监督运行；在用户数据目录的独立目录安装官方 registry 的准确目标版本，不原地覆盖运行目录，不使用 sudo、不全局安装。支持通过正式 CLI 启动的生产服务；源码启动/开发模式仍可检测，明确提示不能一键安装。启动监督器保持原端口与环境，新进程启动失败时回退到旧版本。
- 更新路径指针仅在新版启动成功后原子写入；后续从原 CLI 启动仍使用已更新版本。显式安装更高版本时优先新安装版本。保留旧目录以供回退，不在本次需求清理旧版本。
- Electron 复用 electron-updater 和已有 GitHub 发布源；关闭退出时静默安装，单次操作下载后安装重启；重复操作合并，失败可重试。开发模式禁用安装。
- macOS 的安装包下载和系统更新器准备是两个阶段；下载完成后先执行最终空闲检查，检查通过并进入安装重启阶段后才能调用原生更新器。Squirrel 原生准备会产生退出时安装的副作用，不能把它放在仍可能被空闲检查阻断的下载阶段。阻断时仅保留下载文件，普通退出不得安装该次更新；显式重试仍需重新检查空闲。原生准备属于已授权安装的提交阶段，不再通过后置空闲检查宣称可以取消该安装；不承诺冻结此后外部输入或撤销已提交的原生安装。安装触发失败时保留运行服务，真正退出时执行既有 PTY 清理。
- 首次启动允许 `PORT=0` 自动分配端口，或请求端口被占用时沿用现有可用端口回退；第一次成功就绪握手才记录实际端口。后续升级与回退必须使用并校验该实际端口，不能拿首次请求端口拒绝正常启动。
- 维持现有暂停 Electron 自动发布的约定：没有安装包/更新元数据时显示检测错误，不伪装存在可安装更新。本次不恢复发布流水线，也不实际升级或重启用户实例。
- 所有 HTTP 更新操作沿用登录鉴权，写操作要求 JSON 及自定义请求头；仅固定包名、registry、服务器检测出的版本可执行，客户端不能提交命令、URL 或安装路径。桌面 IPC 仅接受本机应用顶层窗口。

## 验收标准

1. 新版/同版/旧版/非法版本、网络失败、并发检测和重复点击均有测试；自动检查只检测。
2. 忙碌与无法确认状态时不执行升级；下载后变忙不重启，保留已下载版本供显式重试。
3. 安装失败保留旧服务；重启成功保持端口、环境和数据目录；启动失败回退，重启后界面能重连并识别实际版本。
4. 桌面一键下载并重启，无确认授权时不下载安装；安装失败、重复操作与后台检查不会破坏已下载状态。
5. 设置和工作区入口可显示状态、错误与重试；浏览器与 Electron 使用各自通道；桌面/移动端布局可用。
6. 相关测试、完整 TypeScript、改动文件 ESLint 和构建记录实际结果；真实 npm 安装切换、签名 Electron/macOS 更新未执行时明确标记。
7. 回归测试覆盖首次随机端口、请求端口占用回退、后续升级及回退固定实际端口；macOS 下载期间变忙或状态检查失败时不触发原生准备，普通退出无待安装更新，空闲后显式重试可复用下载并完成安装。
8. 安装首次空闲检查尚未结束时即时状态为忙碌；后台检测与安装交错时不丢失用户操作、不重复下载或重启，使用检测后的版本，检测失败或无新版不安装，忙碌阻断后不自动重试。

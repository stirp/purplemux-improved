# 待回答问题的前端通知

## 原始需求

当触发 ask user question 时，由于需要人的确认，因此需要前端向人发起通知，以便尽快完成。

## 范围与约定

- 在交互式问题卡片基线上新增全局通知，覆盖 Claude AskUserQuestion、Codex request_user_input / request_user_input_async 及事件格式的 RequestUserInput。
- 从已有全局 JSONL 状态监听同步待回答问题，不依赖时间线组件挂载。保持 hook 驱动的运行状态及原有回答接口不变，异步问题不将 busy 改成 needs-input。
- 浏览器及移动端出现新的待回答问题时显示持久 Toast，包含项目名、问题摘要和“打开”操作；当前会话也提醒。隐藏页面保留提醒，回到页面后可见。问题提醒独立于“任务完成 Toast”开关。
- Electron 复用原生通知通道，遵守现有 notificationsEnabled 开关；每条问题通知携带自身的会话和调用标识，点击不会误开后来通知的会话。普通浏览器本次以应用内提醒为范围，不新增系统权限申请。
- 按 Tab、会话身份和工具调用 ID 去重；重复同步、重连、组件重新挂载不重复提醒。同一文字的新调用仍提醒。首次连接仅提醒当前待回答问题，时间线历史分页不触发通知。
- 已回答、取消、会话切换或 Tab 删除后撤销对应 Toast；打开目标也关闭 Toast，导航前校验会话仍匹配。发送失败不清除待回答状态。新普通用户消息视为开启下一轮并清除上一轮遗留问题；异步格式化回答只清除匹配的问题。
- 运行快照沿用有界 JSONL 尾部扫描，最多读取 128 KiB；超出窗口的旧问题不作为待回答问题同步。不引入历史全量扫描或新的持久化设置。
- 新增状态字段为可选，旧客户端忽略；新客户端连接旧服务端保持原行为。
- 审查修正：Codex 回答同时兼容 `event_msg.user_message` 和 `event_msg.item_completed` 中的 `UserMessage` 文本块；同一回答的两种表示不重复消费，不清除其他未回答问题。新问题之后的相同答案仍可正常提交。
- 审查修正：问题原生通知仅使用自身标识导航，不修改普通任务完成/需要输入通知的共享点击目标，两类通知交错出现时各自定位正确。

## 验收标准

1. Claude 与 Codex 两种工具调用格式及 Codex 事件格式均能提取待回答问题；异步工具返回不误判为回答。
2. 未打开对应项目/Tab、当前 Tab、移动端及隐藏页面均保留应用内提醒，并可导航到对应会话。
3. 重复同步、重连与重新挂载去重，不同问题、不同会话分别提醒。
4. 回答成功、取消、切换及删除撤销提醒；发送失败或无关状态更新不误清除。
5. 保留任务完成通知及 CLI 状态行为；原生通知遵守开关，失败不影响 Toast。
6. 相关测试、完整 TypeScript、改动文件 ESLint 及构建通过，记录实际验证范围。
7. `UserMessage` 完成事件使已回答问题从运行快照中消失；双格式回答的两种顺序均保留其他未回答问题。普通通知先出现、问题通知后出现以及相反顺序均导航正确。

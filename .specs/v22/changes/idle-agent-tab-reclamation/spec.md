# 闲置 Agent 页签回收与会话保留

## 原始需求

“还有，如果一个工作里的 session 很久没有对话，也支持回收 tab 页签，释放进程资源，但是从会话里还是可以 resume 相关会话。这主要是为了节省系统进程资源和内存。”

## 行为约定

- 设置 → 本机进程增加闲置页签回收。默认手动执行，自动回收默认关闭，可显式开启；默认闲置阈值 60 分钟，可设置 15～10080 分钟。
- 全局策略保存于 workspaces.json，作用于应用管理的 Claude/Codex Agent 页签。手动回收提供当前候选列表及确认，服务器仅处理请求中列明且重新检查仍满足条件的页签；自动回收每分钟检查一次，无需保持浏览器打开。
- “闲置”采用原生会话最新写入/事件、最新用户输入、Agent 启动时间中的最新时间。必须有真实可读原生记录、合法会话 ID，运行状态为 idle、ready-for-review 或 cancelled，且实时原生快照明确 idle、非 stale。
- busy、needs-input、unknown、inactive、压缩中、权限等待、排队/发送/等待确认中的输入一律跳过。缺少状态、会话证据、工作目录或查询失败时不猜测回收。
- 只回收已知 Agent/shell 包装链的终端；存在工具、后台任务、独立子代理或多 pane 时跳过，避免因为对话暂时无更新而终止仍在执行的工作。外部终端、普通 terminal、网页和 diff 不在范围内。
- 回收前持久化原生身份、目录和恢复导航目标，并保留历史轮次、标题、标签及人工状态。不设置删除/隐藏标记，不删除 JSONL、目录或工作区。
- 复用既有关闭 Tab 的终端清理与布局广播，检查终端确实关闭后再移除页签。回收最后一个页签后保留空工作区，不自动补开 Agent；服务重启不会按已回收页签自动恢复。
- 用户在 Sessions 中重新打开时，沿用既有恢复入口，为原 session ID 创建页签，并使用保留的会话目录（多目录工作区不错误切换为第一个目录）。
- 自动扫描与手动回收在同一服务内串行。保存失败不停止，预览后的新对话/输入、身份变化或策略变化会使候选失效；逐项返回回收/跳过结果，不把部分失败显示为全部成功。
- 本增量增加资源回收，不替代历史删除的默认删除原生记录行为；回收操作始终保留历史。外部进程接入流程及其信号约定不变。

## 验收

1. 默认自动关闭、60 分钟阈值，设置严格校验、持久化及失败可重试。
2. 明确空闲且超时的 Agent 页签可回收；忙碌、等待确认、排队输入、后台进程和证据缺失者受保护。
3. 回收前保存恢复索引，保存失败不关闭；状态/输入/会话改变时不关闭；关闭未成功时保留页签。
4. 回收后原生文件、历史及工作区保留，从 Sessions 使用原身份和目录恢复；空工作区重启不补建 Agent。
5. 手动确认仅影响预览目标；自动运行不依赖浏览器，服务退出清理定时器，避免重叠扫描。
6. 执行相关测试、完整 TypeScript、改动文件 ESLint、构建或浏览器验证；分别记录模拟与实机范围。

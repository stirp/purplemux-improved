# 闲置 Agent 页签回收与会话保留

## 原始需求

“还有，如果一个工作里的 session 很久没有对话，也支持回收 tab 页签，释放进程资源，但是从会话里还是可以 resume 相关会话。这主要是为了节省系统进程资源和内存。”

## 行为约定

- 设置 → 本机进程增加闲置页签回收。默认手动执行，自动回收默认关闭，可显式开启；默认闲置阈值 60 分钟，可设置 15～10080 分钟。
- 全局策略保存于 workspaces.json，作用于应用管理的 Claude/Codex Agent 页签。手动回收提供当前候选列表及确认，服务器仅处理请求中列明且重新检查仍满足条件的页签；自动回收每分钟检查一次，无需保持浏览器打开。
- “闲置”采用原生会话最新写入/事件、最新用户输入、Agent 启动时间中的最新时间。必须有真实可读原生记录、合法会话 ID，运行状态为 idle、ready-for-review 或 cancelled，且实时原生快照明确 idle、非 stale。
- busy、needs-input、unknown、inactive、压缩中、权限等待、排队/发送/等待确认中的输入一律跳过。缺少状态、会话证据、工作目录或查询失败时不猜测回收。
- 只回收已知 Agent/shell 包装链的终端；存在工具、后台任务、独立子代理或多 pane 时跳过，避免因为对话暂时无更新而终止仍在执行的工作。外部终端、普通 terminal、网页和 diff 不在范围内。
- 回收前持久化原生身份、目录和恢复导航目标，并保留历史轮次、标题、标签及人工状态。不设置删除/隐藏标记，不删除 JSONL、目录或工作区。
- 复用既有关闭 Tab 的终端清理与布局广播，检查终端确实关闭后再移除页签。回收最后一个页签后保留空工作区，不自动补开 Agent；服务重启不会按已回收页签自动恢复。
- 用户在 Sessions 中重新打开时，沿用既有恢复入口，为原 session ID 创建页签，并使用保留的会话目录（多目录工作区不错误切换为第一个目录）。
- 自动扫描与手动回收在同一服务内串行。保存失败不停止，预览后的新对话/输入、身份变化或策略变化会使候选失效；逐项返回回收/跳过结果，不把部分失败显示为全部成功。
- 本增量增加资源回收，不替代历史删除的默认删除原生记录行为；回收操作始终保留历史。外部进程接入流程及其信号约定不变。

## 验收

PR #71 修正：销毁 tmux 会话前，仅向已核验的末端 Agent 发送 SIGTERM，等待 Agent 及已知 Node 包装器退出；不先终止父 shell。超时、查询失败或出现新进程时保留真实 tmux 会话及页签，不升级 SIGKILL。确认只剩原有 shell 后才执行终端清理，避免留下无法重连的空壳页签。

1. 默认自动关闭、60 分钟阈值，设置严格校验、持久化及失败可重试。
2. 明确空闲且超时的 Agent 页签可回收；忙碌、等待确认、排队输入、后台进程和证据缺失者受保护。
3. 回收前保存恢复索引，保存失败不关闭；状态/输入/会话改变时不关闭；关闭未成功时保留页签。
4. 回收后原生文件、历史及工作区保留，从 Sessions 使用原身份和目录恢复；空工作区重启不补建 Agent。
5. 手动确认仅影响预览目标；自动运行不依赖浏览器，服务退出清理定时器，避免重叠扫描。
6. 执行相关测试、完整 TypeScript、改动文件 ESLint、构建或浏览器验证；分别记录模拟与实机范围。

### 跨域误判修正

回收 POST 与策略保存 PATCH 复用[本机进程管理的同源防护修正](../local-agent-process-management/spec.md#停止操作跨域误判修正)，均携带 `X-Purplemux-Process-Action: 1`。反向代理改写 Host 不阻断同源操作；真实跨源请求返回 403 且不调用保存/回收服务。预览、策略默认值和回收语义不变。

### 超期不回收修正（2026-10-28）

用户反馈：开启 60 分钟自动回收后，多个启动多日的 Codex 仍在运行，预期终止闲置进程释放内存，保留会话供下次 resume。

- 本次修正属于本需求的启动链兼容缺陷，关联 [Codex 启动生命周期](../codex-launch-lifecycle/spec.md)及 [Agent 环境启动器](../../../v20/requirements/per-agent-environment.md)。进程列表日期是启动时间，不等同于最后对话时间。
- “已知包装链”包含应用自己的 Codex 固定路径启动器、Claude 当前 bootstrap 和旧版完整内联启动器，以及真实路径指向已知 Agent npm 包的 bin 符号链接。必须最终连接到同 provider 的实际 Agent；仅有启动器、同名其他路径、任意 node -e、provider 不匹配均不能回收。
- Claude 已知启动器后的 shell 回退链可通过，但实际 Agent 后的工具、后台进程、独立子代理、多分支或多 pane 仍保护。不因修正包装器识别而放宽运行状态、原生记录及输入核验。
- 预览和退出使用一致的进程角色判定；仅向末端实际 Agent 发送 SIGTERM，等待全部 Agent/npm 包装器/应用启动器退出，仅剩原有 shell 后才清理终端。启动器存活、身份变化或查询失败时保留终端及页签。
- 验收覆盖两种应用启动器、npm bin 链、Claude shell 回退、假冒/异类/后台进程拒绝、包装器延迟退出及超时；回归确认先保存恢复索引，再停止进程，历史与原目录恢复保持不变。截图机器的具体 PID 未读取时，不把本机或模拟证据声称为现场逐进程诊断。

### 代码评审修正（2026-10-29）

- P1：实际 Agent 有任何后代都不允许回收，包括 Node/npm 形式的 Claude 主进程。只有已确认的应用启动器及 Codex npm 转发脚本可以继续到下一进程；Codex npm 转发脚本必须直接连接原生 Codex，不接受 shell 或另一个 Node Agent。预览与关闭前复检共用此边界，拒绝链不得发送信号。
- P2：旧 Claude 内联启动器按旧生成器的 `trim().replace(/\n\s*/g, ' ')` 实际参数验收，不能只测试原始多行常量。允许已知开发、服务端与 webpack 压缩构建中的环境校验函数形式，使用静态语法结构比对消除空白、引号、括号差异；不执行待识别脚本。未知构建变体、增加/修改语句或字面量、任意 node -e 均拒绝，不以宽泛关键词匹配放行。
- 验收新增：应用 bootstrap → Node/npm Claude → 同 provider 独立子进程必须被拒绝且无 SIGTERM；无后代的 Node Claude 正常回收；Codex npm → native 保持可用。旧生成器的真实单行 argv 和已知压缩构建变体能够预览/关停，改动脚本仍拒绝。

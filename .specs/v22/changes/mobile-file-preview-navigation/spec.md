# 移动端文件预览返回入口

## 用户原始需求

在移动端预览文件的时候，没有关闭或回退按钮，不够友好。

## 范围和行为

- 替代基线中回复、计划文件链接在新页直接打开读取接口的行为：改为在当前页打开 `/file-preview` 统一预览页面。保留同一浏览器标签的 sessionStorage 工作区和活动会话选择；仍可通过浏览器菜单另开页面。
- 页面顶部始终显示带文字的“返回”入口及文件名，触控区域至少 44px，适配安全区、窄屏及深浅主题；文件内容在下方独立滚动，不遮挡返回入口。
- 链接记录来源页面（保留查询参数及 hash）。“返回”直接进入该来源，沿用已有 sessionStorage 恢复工作区和会话，无须浏览器提供历史或允许脚本关闭标签页。直接打开或来源无效时返回应用首页。仅接受应用首页的查询参数/hash，拒绝外站及其他路径，避免开放重定向。
- 文本、HTML、图片及 PDF 共用导航外壳；原文件下载和 API URL 保留，文本行号定位和 HTML 相对资源继续工作。内容加载失败时返回入口仍可用。
- 复用现有认证、文件读取和文本渲染。仅将文件响应的 `frame-ancestors 'none'` 调整为 `'self'`，允许本应用内嵌；预览内容仍禁止脚本、表单和顶层导航，不放宽文件范围及原有资源限制。
- HTML、SVG 和文本内容继续受 API CSP 及 iframe sandbox 约束；PDF 使用浏览器原生阅读器，外层 iframe 不加 sandbox（Chromium 会因此禁用 PDF 插件），接口继续强制 `application/pdf` 和 `nosniff`。
- 桌面可用编辑器、普通网页链接和附件入口不变；无可用编辑器时同样使用预览页面。不新增配置、依赖或文件编辑能力。

## 验收标准

| 编号 | 条件 | 验证方式 |
| --- | --- | --- |
| PN-01 | 回复与计划文件链接包含预览地址、原路径、行号和来源；桌面编辑器不受影响 | 组件及 URL 测试 |
| PN-02 | 返回来源会话；直接访问、外站或非法来源回退首页 | 页面及 URL 测试 |
| PN-03 | 320px/390px 下按钮可见且至少 44px，长文件名及滚动不遮挡导航 | 浏览器检查 |
| PN-04 | 文本行号、HTML 相对资源、图片/PDF及错误响应保留顶部导航；脚本不能运行 | 接口测试和浏览器检查 |
| PN-05 | 相关测试、完整 TypeScript、改动文件 ESLint 通过，记录实际验证限制 | 命令验证 |

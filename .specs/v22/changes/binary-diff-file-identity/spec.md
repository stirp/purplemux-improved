# 二进制差异文件名称与独立展开修复

## 用户原始需求

“修复二进制文件被显示为‘file’的问题，而且点击其中一个就会把所有名为‘file’的文件都展开。”

## 范围与行为约定

- 补充差异浏览基线的路径解析约定：没有 `---` / `+++` 头的二进制差异，从 `diff --git` 头恢复旧、新路径；重命名元数据和显式文件头提供更准确的路径时优先使用。
- 支持新增、修改、删除、重命名的二进制文件，显示真实仓库相对路径；支持空格、中文及 Git 引号/转义路径。只有元数据的文件同样保留路径。
- 路径中的 U+FEFF 是文件名字符；解码八进制 UTF-8 时必须保留，即使它出现在某段转义字节的开头，也不能按文本 BOM 丢弃。仅相差该字符的文件须保持不同标识和编辑器目标。
- 差异接口的补丁输出显式使用 `a/`、`b/` 前缀，覆盖工作区已跟踪/未跟踪文件、普通历史提交和根提交；不受 `diff.noprefix`、`diff.mnemonicPrefix` 或自定义源/目标前缀影响。仅通过命令参数约束本次输出，不修改用户或仓库 Git 配置；解析器继续消费统一格式。
- 沿用仓库、比较引用和旧/新路径组成的稳定标识；不同目录下同名文件独立展开/收起，刷新和顺序变化不串联状态，默认收起。
- 保留新增、删除、重命名标记及 `Binary file` 提示，不增加二进制预览；已有文本 hunk、增删统计及原始文件头不受影响。
- 编辑器入口使用恢复后的真实路径，删除文件继续不提供入口。桌面与移动端共用解析；现有差异模式、配置保存、文件访问和接口不变。
- 不扩展 Git diff 接口的未跟踪文件枚举逻辑，不修改 Git 配置，也不引入依赖。

## 验收标准

| 编号 | 条件 | 验证 |
| --- | --- | --- |
| BF-01 | 多个无文本文件头的二进制差异展示各自路径，新增/修改/删除标记正确 | 解析测试、组件测试 |
| BF-02 | 空格、中文、引号、反斜杠及重命名路径正确，纯元数据差异可识别 | 解析测试 |
| BF-03 | 点击仅切换目标文件；重排及刷新保留正确展开状态，切换仓库/引用不串联 | 真实组件交互测试 |
| BF-04 | 编辑器打开正确文件，删除文件无编辑器入口；二进制展开不请求文本内容 | 组件测试 |
| BF-05 | 文本差异、原始文件头、hunk 与统计保持正确 | 解析及既有编辑器回归测试 |
| BF-06 | 相关测试、完整 TypeScript、改动文件 ESLint 及构建通过，实际限制如实记录 | 命令验证 |
| BF-07 | U+FEFF 在转义段首及段内均保留；仅相差该字符的两个二进制文件独立展开，编辑器路径包含正确编码 | 解析及桌面/移动端组件回归测试 |
| BF-08 | 不同 Git 前缀配置下，工作区（含未跟踪文件）、普通提交及根提交差异均恢复真实二进制路径；文本文件头和真实路径中的前缀样式目录保持正确 | 临时仓库真实 Git 接口回归测试 |

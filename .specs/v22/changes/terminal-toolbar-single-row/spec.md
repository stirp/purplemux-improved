# 终端命令与按键共用单行

## 原始需求

“这两排按钮应该可以优化一下，放在一排，一个从左向右，一个从右向左，可以节省空间。”截图为终端底部自定义命令栏和虚拟按键栏。

## 行为与覆盖关系

- 普通终端的两组按钮共用一行：自定义命令组从左侧排列，虚拟按键组靠右侧排列，两组设置入口分别固定在最左、最右。保留组内配置顺序，不反转按键文本或存储顺序。
- 替代两栏各占一行的布局；两组存在时分配可收缩的空间，以分隔线区分，各自横向滚动且不换行、不撑宽页面。仅命令组存在时使用整行。
- 桌面沿用按键栏 auto/always/never 策略；Agent 面板原有内联按键栏不变。
- 移动端保留连接时的输入框及发送按钮，命令与按键在其下共用一行；断线时仍能管理命令，禁用执行，隐藏输入框及按键，沿用既有行为。
- 同一移动端标签内，连接、断线、重连不得卸载命令编辑实例；已打开的管理弹窗、未保存名称及命令草稿保持不变，连接变化不得自动保存或执行命令。
- 复用原有配置、管理弹窗、命令发送和修饰键逻辑，不增加 API、存储字段或依赖。

## 验收标准

1. 桌面同时显示两组时只有一排按钮，命令靠左、按键靠右，设置入口可见。
2. 320px、390px、截图约 567px 及宽屏下不换行、不重叠、不出现页面横向溢出；超长列表可分别滚动到末尾。
3. 按键栏隐藏时命令仍显示并占用整行；空命令列表及全部按键隐藏时可进入设置。
4. 移动端保留输入与发送功能、修饰键状态和断线行为；桌面 Agent 内联按键不受影响。
5. 运行相关既有测试、完整 TypeScript、改动文件 ESLint，并完成浏览器布局验证或构建；记录未验证的限制。
6. 移动端新增或编辑命令时，经历 connected → disconnected → connecting → connected 后，弹窗保持打开、草稿完整，断线期间命令不可执行、输入区及按键隐藏，重连不自动发送。

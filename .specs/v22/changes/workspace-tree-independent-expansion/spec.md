# 工作区树独立展开与收起

## 用户原始需求

“随着界面改造, 现在侧边栏的树形结构已经比较明显了, 那么非叶子应该是支持打开或收起的, 并且也没有必要打开另一个项目的树就把之前的收起来.”

## 范围与覆盖关系

- 替代工作区管理基线中“根据当前激活路径展开祖先，收起无关子工作区”的互斥行为：每个项目独立展开，多棵树及兄弟分支可同时打开。
- 桌面非叶子箭头改为可操作按钮，仅展开/收起，不切换当前项目；点击名称仍选择项目并揭示其路径。叶子没有展开按钮。按钮具备项目名称、展开状态和键盘操作，不触发改名、菜单及拖拽。
- PR #52 事件隔离补充：右键点击展开按钮及其 SVG 图标，不打开项目菜单、不改变选中或展开状态；项目行自身的右键菜单继续可用。
- 移动端沿用点击项目选择并展开/收起、Tab 点击导航的交互；存在子项目或 Tab 的项目可折叠，空叶子仅选择。替代重开抽屉清空其他展开项的行为，重开保留本次导航状态。
- 收起父节点隐藏全部后代及其 Tab，保留后代自身展开状态，重开父节点可恢复。收起当前项目不切换活动项目、不关闭终端。
- 初始化仍揭示当前项目及其祖先；快捷键、会话跳转、新建/接管或外部切换项目时追加揭示目标路径，不收起其他树。
- 显式导航即使目标 ID 与当前项目相同，也必须重新揭示目标路径；普通列表同步不得触发该行为。移动端行内选择并收起不属于外部导航。
- 新建/接管完成的旧异步回调应提交展开请求，在当前最新列表中解析目标路径；若目标尚未进入列表，保留请求直到节点可解析。搜索中的请求不修改原展开集合，也不在清空搜索后补执行。
- 搜索只临时展开匹配祖先；搜索中选择项目不改变搜索前展开集合，清空恢复。搜索期间桌面展开按钮禁用，移动项目仍可选择；菜单、分组折叠、拖拽和状态语义沿用前置规格。
- 展开集合是导航组件生命周期内的交互状态，刷新后按当前项目初始化；不新增持久化偏好、接口、配置迁移或依赖。数据同步与重连不重置已有展开集合；删除项不渲染，孤儿和循环节点保持可访问。

## 验收标准

| 编号 | 条件 |
| --- | --- |
| TE-01 | 桌面箭头可点击、键盘激活，展开/收起不选择、改名或拖动项目；右键按钮及 SVG 不打开项目菜单，项目行右键仍可用；叶子无按钮 |
| TE-02 | 打开 A、B 和兄弟分支后均保持展开，选择叶子也不会收起其他树 |
| TE-03 | 收起任意祖先隐藏整个子树，重新打开恢复子节点状态；活动项目保持不变 |
| TE-04 | 初始及外部导航揭示目标路径，工作区重排、同步不清空展开状态，孤儿/循环安全 |
| TE-05 | 桌面与移动搜索点击、清空恢复原展开集合，不写配置 |
| TE-06 | 移动空项目可选，Tab 导航、抽屉重开及多个项目展开正常，菜单和触摸回归通过 |
| TE-07 | 父节点收起时，通过新建前捕获的回调选择新增子节点，或先请求再同步节点，均展开最新目标路径 |
| TE-08 | 当前子项目被祖先隐藏后，反复通过 Sessions 或工作区快捷键选择同一 ID 均可揭示；普通同步及移动行内收起保持原状态 |

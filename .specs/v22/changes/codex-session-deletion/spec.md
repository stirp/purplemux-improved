# Codex 会话删除一致性

## 原始需求

项目中 Codex 执行 `/review` 后，关闭 Tab 并删除相关会话，再通过项目“+”打开会话列表，仍出现已删除父会话和可恢复的 review 子会话。预期两个会话均不可见，Codex 原生也不能恢复已删除的父子会话。

## 行为与边界

- 增量补充会话生命周期基线：确认删除 Codex 原始记录时，按明确的父子关系收集 review 及其他 subagent 后代（包含归档记录），先删后代再删父会话，全部调用 Codex 原生 `thread/delete`，不直接修改 Codex 数据库。
- 关系使用 `parent_thread_id`、`source.subagent.thread_spawn.parent_thread_id`，兼容旧 subagent 的 `forked_from_id`。普通用户 fork 不作为子会话；不按项目路径或时间推断关系；无明确关系的旧文件不自动删除。
- 所有已发现目标在开始删除前检查本应用活动 Tab，逐个原生删除失败即报错；允许部分完成后重试，不把部分失败报告为成功。不改变既有默认勾选、最终确认、仅隐藏选项和 Claude 删除语义。
- 每个原生成员删除成功后立即清理其应用内记录：保存隐藏标记，清除全部历史轮次、工作区索引、标题及人工状态，保存删除身份并广播历史同步。历史入口与工作区删除入口共用该清理逻辑；后续成员失败仍保留此前成员的清理结果，不隐藏失败或尚未执行的成员。仅隐藏模式仍只处理选中的身份。
- 项目 Codex 会话列表不展示内部 subagent（包括 review），历史隐藏过滤保持有效。
- 删除成功及历史同步/重连使项目会话列表缓存失效；未挂载的列表缓存也清除，避免再次打开或切换项目读取旧记录。不更改人工状态与 Tab 关闭语义。
- 不启动后台清理，不自动清理此前残留的真实会话；已有已知父 ID 可通过原删除流程重试清理。

## 验收条件

1. 默认、旧格式、归档、多级后代精确清理；同项目无关会话、普通 fork 和无关联 review 保留。
2. 活动后代阻断删除；初始化、扫描或原生删除失败不假报成功；重试可处理父文件已缺失的残留后代。
3. Codex 项目列表过滤各类 subagent，正常主会话元数据、排序、并发缓存行为保持。
4. 删除后即使在去重窗口内重新打开“+”列表，也不会显示旧父会话；多客户端历史同步与重连清除旧缓存。
5. 相关自动化测试、完整 TypeScript、改动文件 ESLint 通过；隔离 Codex 原生集成验证删除后列表与读取结果，明确记录未执行的浏览器/实机项目。
6. 子会话曾单独恢复并留下多轮历史、索引和人工状态时，删除父会话后不再被 collectWorkSessions 展示或影响汇总；父/兄弟删除失败时，已删除子会话仍清理并广播，失败身份保留，迟到历史或 inactive Tab 不使已删身份复活。

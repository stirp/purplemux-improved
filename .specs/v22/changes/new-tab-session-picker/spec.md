# 新建 Tab 直接展示应用入口与可恢复会话

## 原始需求

“由于现在我们会自动回收会话，新建 tab 的时候有必要把可选择的会话都显示出来，因此不应该显示为 codex，claude，terminal 和会话列表，而是显示应用的入口，以及可选择的会话列表。”

## 范围与行为

- 替代新建菜单中的并列类型列表：桌面弹层和移动端弹窗上方为应用启动入口（Claude、Codex、Terminal，桌面另有 Web Browser），下方直接列出当前工作区的可选择会话，不再提供需要先创建 Tab 的“会话列表”按钮。
- 打开选择器只读取数据，不创建终端。空工作区、全部 Tab 已回收时仍可读取会话。
- 合并工作区各目录的原生 Claude/Codex 列表和应用保留的历史/回收记录；按 provider 与原生 ID 去重，按最近活动排序，保留自定义标题与原恢复目录。原生 Codex 扫描沿用现有接口时间范围，应用保留的会话不受该范围限制；不展示已隐藏/删除项或其他项目记录。
- 支持搜索标题、会话 ID、提供方和目录；列表滚动展示所有返回项。Claude 列表通过显式 `all=true` 一次返回目录内全部可见会话，服务端每个请求只执行一次扫描；未传该参数的旧调用保留原分页语义。
- 选择已打开会话复用现有 Tab；已回收会话按原 provider、session ID 和目录恢复到发起入口的 pane。安装检查、权限配置、创建失败提示及 cwd 失效保护沿用基线。
- 加载、空结果、部分/全部读取失败、重试及恢复中状态明确可见；一个提供方失败不遮蔽其他成功返回或保留的会话。操作失败保留选择器并可重试；请求中防止重复点击。
- 桌面快捷键仍可打开选择器；支持键盘访问应用和会话，移动端窄屏不横向溢出。保留既有 agent-sessions Tab 类型、其他会话入口和自动回收策略。

## 验收

1. 桌面和移动入口直接显示应用与会话，无独立“会话列表”创建按钮；取消不创建进程。
2. 空项目无 tmux 时能查询原生列表并显示回收记录，多目录记录保留恢复目录。
3. 两类提供方合并、去重、标题、排序、搜索、隐藏项及 Claude 全量读取正确，旧分页调用兼容。
4. 已打开会话不重复创建；已回收会话正确恢复到发起 pane，失败可重试；新建应用行为兼容。
5. 测试覆盖空项目查询、部分失败与恢复参数；运行完整 TypeScript、改动文件 ESLint 和相关回归，执行构建或浏览器验证并如实记录。

## 2026-10-29 评审修正

- 工作区共享目录时，以既有工作流/历史/活动 Tab 汇总的会话归属为准。已归属其他工作区的 provider + session ID 必须从原生候选中排除；尚未有归属的原生会话仍可选择，两种 provider 的同名 ID 相互独立。
- 同一应用页面中的新建选择器按工作区共享进行中操作状态，从安装检查开始直到创建/恢复及布局定位结束。关闭、重开或同时打开另一 pane 的选择器不能绕过互斥；不同工作区不互相阻塞。成功、失败及取消安装检查均释放状态，失败可重试；已卸载实例的完成回调不能关闭后来重开的选择器。
- 替代逐页加载：每个目录的 Claude 请求使用 `all=true`，不再存在“第一页成功、第二页失败”的丢数据路径；超过 100 项仍完整返回，不因页数重复扫描。其他 provider/目录失败时仍保留成功来源与应用回收记录。
- 回归覆盖共享目录的活动/回收/历史归属、关闭重开时的慢恢复/失败重试、全量请求的扫描次数和旧分页兼容。

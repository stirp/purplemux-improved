# Codex 启动生命周期

## 原始需求

用户新建 Codex 会话后，在输入聊天内容时界面变成没有 Codex 会话；再次启动后仍显示之前输入的内容。要求查明原因并修复。

2026-10-21 后续修正：用户在工作区 `ws-Ax8Lpl` 连续创建 Codex 会话，启动命令均输出 `This operation was aborted` 并以 1 退出。修复同一启动器的慢响应等待及错误诊断。

2026-10-21 Chat 状态修正：用户指出 TUI 中 Codex 已启动，但 Chat 显示启动失败。现场 `ws-OeRRes/tab-zaoVW0` 显示 Codex v0.163.0 输入提示，服务端 `cliState=idle`、`agentSessionId=null`。这与启动器退出是不同问题，不能沿用之前的故障归因。

## 调查与范围

- 现场保留的四个终端中存在 `fetch failed`、`purplemux port file is missing`，均来自 Codex 启动器。尚未获知用户此次异常的具体标签和时间，不将这些记录断言为同一次故障。
- 当前服务在 HTTP 监听及端口、令牌、Hook、工作区提示准备前调用自动恢复；Codex 启动器需要请求本服务取得参数和环境，失败会直接退出。此问题独立于 Codex 原生崩溃。
- 输入文字由现有 Web 输入框按 tab ID 保存草稿，重启同一标签后恢复文字；继续保留这一防丢失行为。

## 行为约定

- 增量明确 provider-core 的启动前置条件：服务自动恢复必须在实际监听端口、Hook/端口文件、CLI 令牌及工作区提示准备完成后执行。维持先初始化状态管理器，随后发起恢复，确保记录启动宽限期。
- Codex 新建和恢复共用启动器：端口暂不可读、连接失败、HTTP 502/503/504 时，在 60 秒总期限内以 500 毫秒间隔重试；每次请求（含读取响应体）使用剩余总期限，不再每 5 秒中断慢响应。此修正替代原 15 秒总期限、5 秒单次期限，也更新 [开发请求中断修复](../dev-http-abort-handling/spec.md) 所引用的启动期限；该需求的请求错误边界保持不变。
- 每次重试重新读取端口和令牌；仅成功校验一次参数和环境后启动一个 Codex 子进程。HTTP 认证/参数错误、其他 HTTP 错误和响应格式错误立即失败，不重试，不启动子进程。
- 总期限耗尽时保留实际错误信息并非零退出；请求超时须明确提示等待 purplemux 的 `/api/codex/launch-args` 超过 60 秒，并建议检查服务和开发编译日志，不再仅输出原始 AbortError。不输出令牌、环境变量或提示词。不无限等待、不自动重启已经运行或正常退出的 Codex，不自动发送用户草稿。
- 沿用现有权限、环境合并、参数转义、原生会话及进程退出语义；不修改用户 Codex 配置、自动回收策略和聊天输入协议。

### Chat 启动状态

- 替代 TUI ready 基线以等待时长判定失败的条款及当前 UI 的 10 秒无条件失败：桌面和移动端共用检测逻辑；计时结束本身不是进程失败证据。
- 已收到有效工作状态或检测到 Codex 运行，立即退出启动页进入 Chat，不要求会话 ID 或第一条消息，也不发送输入、不重复启动 Codex。
- 启动检查至少等待 60 秒（覆盖启动器取参期限），并且只有期限之后发起的成功检测明确返回 `running=false` 才显示失败。请求失败、超时、无效响应或其他代理运行不能证明 Codex 启动失败，保持等待；后续检测成功自动恢复。
- 复用 `/api/check-agent`，每次只保留一个检查请求，设置请求期限、卸载取消和过期结果保护；不让旧检查覆盖较新的运行状态。切换 Tab 或会话时重新计时。
- 保留现有权限/信任/升级提示优先级、真实退出行为、Claude 启动 UI 与服务端工作状态来源。

## 验收

1. 服务自动恢复发生在监听、端口/Hook、令牌及提示文件准备完成之后，且状态管理器已初始化。
2. 暂缺端口、网络失败及 502/503/504 后恢复，均只启动一次；重读实际端口/令牌；单次慢请求和持续失败受到期限约束。
3. 认证拒绝、无效参数/环境及不可重试错误立即失败；退出和 resume 参数、环境合并兼容。
4. 自动化覆盖真实生成的启动器，并执行相关回归、完整 TypeScript、改动文件 ESLint、构建；区分模拟与现场证据。
5. 响应头或响应体延迟超过原 5 秒及 15 秒期限、但在 60 秒内返回时，新建/恢复均只启动一次；永久无响应在 60 秒结束，先发生重试时不重置总期限；完成后无遗留计时器。
6. Chat 在 10 秒及 60 秒后没有检测证据时都不误报失败；`idle` 或 Codex `running=true` 且会话 ID 为空时进入 timeline。60 秒后新检测确认未运行才显示失败，运行后自动恢复。
7. 覆盖 HTTP/网络/响应体超时、无效响应、其他代理、过期响应、卸载和切换会话；请求不重叠，桌面和移动端复用同一实现。执行相关组件/状态测试、完整 TypeScript、改动文件 ESLint 和构建，如实记录浏览器验证限制。

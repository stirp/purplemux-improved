# 删除项目时可同时删除对应 Worktree

## 用户需求与范围

用户反馈删除 worktree 项目后仍需手动清理磁盘工作树，并确认采用“删除项目时提供同时删除对应 worktree 选项，复用安全检查”的方案。
覆盖桌面侧栏与移动项目菜单，不改变 CLI、普通项目删除 API、分支删除或批量清理行为。

## 行为约定

- 增量补充生命周期基线的“移除子工作区与删除磁盘 Worktree 是不同操作”：两种操作仍独立，但项目确认框可显式选择同时删除。
- 桌面与移动使用同一确认组件。默认不勾选；不勾选时保留原项目、会话清理语义，明确磁盘目录保留。
- 打开确认框后通过现有总览识别与当前项目关联的非主工作树，不依赖 parentWorkspaceId 或创建时保存的分支，不选择同仓库的其他工作树。
- 仅唯一对应工作树可联动删除。普通项目、主工作树不展示该选项；多个工作树、查询失败或关联无法确认时不允许联动，提示使用 Worktree 管理或刷新，仍可只删除项目。
- 勾选后展示磁盘目录、当前分支、关联项目以及分支保留说明；忽略文件复用既有清单，另行确认后才允许提交。刷新后重置勾选与忽略文件确认，避免沿用旧授权。
- 复用 DELETE /api/workspace/worktrees，传递确认时的目录、仓库、HEAD、分支及忽略文件快照；closeIdleSessions=true、deleteBranch=false。不先调用普通项目删除接口。
- 脏文件、主工作树、锁定、状态未知、嵌套/跨目录工作区、活动会话、操作中及快照变化等保护继续由服务端复核，不强制删除、不删除分支、不 fetch。
- 失败保留确认框与项目，显示具体原因，可刷新重试，不能退化为只删除项目。若磁盘删除成功但项目清理失败，展示既有警告、保留未清理的项目，不伪报全部成功。
- 请求进行中禁用重复提交与关闭。成功后使用现有工作区 store 同步列表和活动项目，原有父子关系处理保持不变。

## 验收标准

1. 桌面和移动共用确认组件；每次打开默认只删除项目，取消不发起删除。
2. 普通目录、主工作树不提供联动选项；外部接入且无 worktree 元数据的项目同样可识别；多目标或加载失败不能误删其他工作树。
3. 勾选成功时只调用现有安全删除接口，快照与展示目标一致、保留分支，列表移除服务端返回的项目。
4. 展示忽略文件并要求显式确认；阻断状态禁止提交；服务端拒绝（包括活动会话、快照变化）显示错误且不调用普通删除接口。
5. 刷新和重新打开清除旧确认；失败可重试；清理警告可见；重复提交与关闭保护生效。
6. 运行相关组件与安全删除回归、完整 TypeScript、改动文件 ESLint；按实际运行结果记录构建或浏览器验证及限制。

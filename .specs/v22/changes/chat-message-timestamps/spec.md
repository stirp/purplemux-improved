# 聊天消息发送与回复时间

## 用户原始需求

“现在消息没有时间，不知道是什么时候发出和应答的。这个时间能显示出来吗？”截图为 Codex Chat 中的用户消息和发送状态。

## 范围与行为约定

- 在共用时间线的用户消息、AI 文本回复下方常驻显示时间，覆盖 Claude/Codex、桌面/移动端及历史记录。
- 使用条目已有的毫秒时间戳，在浏览器本地时区显示 `YYYY-MM-DD HH:mm:ss`，悬停提供带 UTC 偏移的完整时间；使用语义化 `time` 元素和 ISO `dateTime`。
- 用户时间位于气泡内部底部、右对齐；AI 时间位于 Markdown 正文外部下方、左对齐。使用弱化文字和小字号，窄屏允许日期与时间之间换行。
- 待确认用户条目沿用现有提交/入队时间，原生记录确认后沿用原生条目的时间；发送、排队、未确认或失败提示继续显示。时间不表示投递成功。
- AI 时间表示对应文本条目的记录时间，不表示整轮任务结束时间。不添加工具调用时间或耗时统计。
- 缺失、非有限值、零、负数或超出日期范围的条目时间不显示，正文仍正常渲染；展示层不补当前时间。旧 JSONL 缺失时间时解析器已有的回退策略维持原样，本次不新增历史时间溯源或数据迁移。
- 本增量新增时间展示条款；基线的消息宽度、分页、长文本折叠、附件、发送确认和重连行为保持不变，不新增设置、接口或持久化字段。

## 验收标准

1. 用户正文、纯图片消息及 AI Markdown 回复均能显示各自有效时间，精确到秒并包含日期。
2. 时间随条目变化更新，历史记录不使用本次渲染时间；无效时间不显示 `Invalid Date` 或虚假的当前时间。
3. 待确认消息的状态提示与时间共存；确认、分页及重连继续沿用已有条目时间。
4. 桌面/窄屏及浅色/深色使用相同组件与主题文字样式，不依赖悬停才能看到时间，不干扰正文折叠与代码复制。
5. 相关回归、完整 TypeScript、改动文件 ESLint 及构建或浏览器检查有实际记录。

# Codex 输入框美元符号联动原生技能选择

## 用户原始需求

“Codex 的输入框开始位置里面输入 $ 符号的时候，对应在 TUI 里面应该是选择 skill，这个行为应该类似输入/”。

## 范围与行为约定

- 扩展原生命令菜单基线的触发入口：Codex 空 Web 输入框键入 `$` 时，与 `/` 一样切换到当前终端，将 `$` 原样发送给 Codex，由真实 TUI 展示可用技能。
- 桌面和移动端复用现有原生菜单流程；不维护 Web 技能列表，不自动追加 Enter，不通过消息队列提交技能选择。
- 单行 `$` 或 `$技能名` 草稿提供与 `/命令` 相同的手动原生菜单入口；非空输入框中的编辑不自动抢占焦点，多行粘贴保留为普通输入。
- 仅 Codex 新增 `$` 支持；Claude 的 `$`、正文中间或前导空白后的 `$` 继续作为普通文本。双方既有 `/` 行为保持不变。
- 沿用连接、会话状态、附件及待发送队列限制。不能进入菜单时保留草稿；输入法组合期间不自动触发。
- 技能菜单展示或 TUI 输入行仍以 `$` 开头时不自动回到 Web 输入框，避免技能选择后尚未提交的 TUI 草稿失去焦点。用户在 TUI 继续输入、提交或取消；恢复普通输入界面后沿用现有稳定检测返回 Web 输入框。
- 手动返回沿用清空终端输入行、恢复 Web 焦点的行为；不发送 Escape/Ctrl-C，不修改配置、持久化结构或服务端 API。

## 验收标准

1. Codex 空输入框输入 `$` 只发送该字符一次，打开终端并聚焦；`/` 在 Codex 和 Claude 中均保持可用。
2. Codex 单行 `$技能名` 可手动转交 TUI，Claude `$`、正文 `$`、前导空白和多行输入不匹配菜单入口。
3. 队列待发送、附件、不可发送状态、会话需要回答或未知状态阻止进入菜单，保留输入内容；输入法组合过程不自动触发。
4. 技能菜单和以 `$` 开头的未提交草稿不会被完成检测提前关闭；取消或提交后恢复普通输入界面才结束原生交互；手动返回可清空输入并恢复焦点。
5. 自动化测试、完整 TypeScript 和改动文件 ESLint 记录实际结果；构建或浏览器验证与实机验收状态分别记录。

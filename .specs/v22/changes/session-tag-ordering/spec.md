# 会话标签拖拽排序

## 原始需求

用户询问排序能力，接受“在管理标签中支持拖拽排序，保存后同步到快捷筛选和标签选择列表”的建议：“就这么处理”。

## 范围与覆盖关系

替代标签基线及浏览增量中“目录按创建顺序、不支持排序”的限制。保留九色色板、会话关联顺序、工作状态、搜索语义和既有保存规则；不新增排序模式或存储字段。

## 行为与验收

1. 管理列表每行提供独立拖动手柄，鼠标/触控拖动与键盘 Space、方向键、Space 可调整顺序，Escape 取消本次拖动；编辑和删除按钮不作为拖动触发器，移动手柄至少 44px。使用项目已有 dnd-kit。
2. 拖动只改变本地排序草稿；显示“取消排序”“保存排序”。取消或关闭丢弃排序草稿；保存成功更新共享标签目录。拖动或保存时禁止关闭，草稿存在时禁用新建、改名和删除，避免交错编辑。搜索非空时禁用排序并提示清空搜索。
3. 保存使用 PATCH /api/session-tags 的 `action: reorder`、`revision`、完整 `tagIds`。tagIds 必须是当前目录 ID 的完整无重复排列，拒绝缺项、未知项、重复项及超出数量上限；仅调整数组顺序，不更改名称、颜色、关联或状态。
4. 沿用 workspace 全局锁、原子写盘及广播，成功推进标签修订号；旧数据沿用当前数组顺序，无需迁移。新标签追加末尾，删除保持其他标签相对顺序。
5. 快捷筛选、筛选弹层、会话标签选择器和管理器使用保存后的统一目录顺序。未保存草稿不影响其他视图；会话卡片仍沿用该会话的关联顺序。
6. 保存失败保留草稿并提供重试；从拖动开始记录修订号，远端新增、删除、改色或排序导致修订冲突时禁止保存，不静默覆盖。无草稿时远端目录更新即时展示；取消冲突草稿后显示最新目录。
7. 验证持久化、校验、并发冲突、失败重试、取消、统一顺序、桌面和移动拖动及键盘操作；运行相关测试、完整 TypeScript、改动文件 ESLint 和真实组件浏览器验证，记录限制。
8. 对话框内拖动时，方向键必须传递给真实 KeyboardSensor；Escape 只取消拖动、恢复可操作状态并保留此前草稿，不关闭弹窗；非拖动时 Escape 沿用关闭规则。回归测试从聚焦手柄派发真实 DOM 键盘事件，不能仅调用拖动回调作为键盘验收。
9. 保存过程中本次成功响应更新修订号、后续目录同步尚未结束时，不显示冲突提示；真正的 409 或保存结束后的远端修订冲突仍须阻止覆盖并保留草稿。使用延迟同步验证中间状态。

# Git 私有索引保留文件变化检测时间边界

## 用户需求与范围

用户要求修复 PR #79 验证中的全量测试失败。Git worktree 提交测试在完整测试运行中报 `noChanges`，单独运行通过；历史发布验证也记录过相同失败。本需求修复私有索引复制丢失原修改时间造成的文件变化漏检，不修改测试数据绕过问题。

## 行为约定

- 补充基线“预览不改变暂存区，确认后内容与预览快照一致”：复制私有索引时保留原索引的修改时间边界，使 Git 继续识别 stat 信息相同但内容变化的文件（racily clean）。时间精度转换不得把边界推迟。
- 预览与提交复核共用同一修复；主仓库及 linked worktree 均适用。索引不存在的首次提交仍受支持。
- 不改变用户的 Git 配置；不改写预览所读取的真实索引；原有锁、冲突、快照一致性及临时文件清理约束继续生效。
- 生成预览后发生同大小改动必须拒绝旧快照提交，不能提交旧内容或报无改动后掩盖变化。

## 验收

1. 使用真实临时 Git 仓库和受控文件/索引时间构造同大小、相同 stat 的修改，原实现稳定漏检，修复后预览包含最新正文且真实暂存区不变。
2. 主仓库及 linked worktree 均可生成并提交该改动；生成后再次修改时拒绝旧快照，HEAD 不变。
3. 原首次提交、暂存与未暂存混合内容、索引锁、Git hook、失败清理测试保持通过。
4. 执行标准 `pnpm test`（含 CLI）、完整 TypeScript、改动文件 ESLint；记录实际结果与运行环境，不通过全局放宽超时或自动重试绕过失败。

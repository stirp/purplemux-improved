# 移动侧栏视觉与触控设计提案

## 用户原始需求

“检查一下移动端的侧边栏显示效果，实在算不上优秀。你能参考 web 的图形，给出合理的移动端设计吗？”

## 交付范围

用户确认：“好，就这么改吧”。本次按已确认设计实现移动导航，维护原型作为设计依据。DETAILED 仅表示规格详情完成，应用及实机验证结果另行记录。

## 现状依据

- mobile-navigation-sheet.tsx 使用固定 w-72 抽屉；路径、分支、端口和状态纵向堆叠；分组及工作树缩进叠加。
- 顶部页签高 28px、文字 11px，分组菜单 24px，底部工具 32px；与 44px 触控目标存在差距。
- 移动端未提供 Web 已有的项目搜索；项目菜单依赖长按，完整路径虽占空间但仍被截断。
- Web 基线截图见前置需求 result/sidebar-comparison.png。本次运行页面跳转登录页，未验证登录后的移动端实际画面。

## 已确认覆盖关系

以下条款为本次实施约定，替代对应移动端基线；其他行为继续沿用前置规格：

1. 移动端采用 Web 的图标、细树线、低饱和紫色选中背景与左侧标记；替代移动端多行元数据常驻及桌面增量中“移动保持原布局”的限制，仅作用于移动导航。
2. 抽屉宽度为 min(视口宽度 - 24px, 400px)，使用可用视口高度并处理顶部、底部安全区；列表单独滚动，顶部与底部稳定。
3. 默认项目行最小 48px、交互热区最小 44px；标题一行省略，长项目名、全部目录、分支及端口可从“更多”面板读取和复制。当前 Tab 可用两行显示标题和摘要；大字号允许行高增长。
4. 每个项目行常显“更多”；操作面板从底部打开，展示完整项目信息和现有操作，管理 Worktree 收入该面板，替代触摸端外露根管理按钮与隐藏齿轮的约定。危险操作仍二次确认，失败保留反馈。长按菜单继续可用，但不作为唯一入口。
5. 点击项目名沿用选择并展开/收起、保持抽屉的行为，空项目同样可选；点击 Tab 沿用导航后关闭抽屉。更多按钮不选择项目、不触发折叠或拖动。
6. 增加与 Web 同规则的名称、路径、分支搜索；保留祖先、临时展开分组，不保存临时折叠结果。搜索时禁用排序、保留长按菜单和原生滚动；输入法组合期间 Escape 不清空查询。无结果提示可清空恢复。
7. 工作阶段和 Agent 运行态沿用现有聚合；“审批中”和“待输入”不合并，未开始不占位。窄屏保留带可访问名称的状态图标，面板显示完整状态；断连不伪装运行。
8. 分组名称弱化、计数右对齐；不额外增加分组的整体缩进。父子节点沿用 16px 缩进及六层上限；深层、孤儿和循环数据保持可访问。
9. 工作区/会话、搜索、新建和设置采用本地化文字。底部新建、工具、设置均具备触控尺寸；工具多时换行，短屏或软键盘弹出时允许整体导航滚动，不能挤没列表。
10. 复用既有数据、搜索、状态与菜单流程，无新后端、配置迁移、最近访问、收藏或自动操作。
11. 详情面板中的目录、分支等元数据保留原生文本选择及复制菜单。工作区行的右键、长按及键盘菜单处理只作用于该行的 DOM 后代，不拦截通过 Portal 渲染的面板事件。

## 应用验收

| 编号 | 条件 |
| --- | --- |
| MS-01 | 320/390/430px 与横屏下，无页面横向溢出；安全区及软键盘不遮挡操作 |
| MS-02 | 浅深色与 Web 语义一致；默认行最小 48px、所有关键操作热区最小 44px；系统放大文字不裁切 |
| MS-03 | 搜索匹配名称、目录、分支，保留祖先；清空恢复偏好，组合输入 Escape 无误清空 |
| MS-04 | 项目、空项目、Tab 导航及更多菜单事件隔离正确；短按、滚动、长按、拖动、取消无回归 |
| MS-05 | 完整元数据无需悬停即可读取；管理、改名、移组、删除可达，失败保留反馈 |
| MS-06 | 审批中、待输入、执行中、完成及断连语义保持，不能仅靠颜色区分 |
| MS-07 | 弹层焦点管理、关闭返回焦点、读屏名称与当前项语义正确；真机验证独立记录 |
| MS-08 | 详情目录、分支的原生 contextmenu、菜单键及 Shift+F10 不被行级处理取消；工作区行的菜单与长按仍正常 |

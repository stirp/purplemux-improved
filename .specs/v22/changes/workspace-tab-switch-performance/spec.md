# 工作区和会话切换性能优化

## 用户原始需求

“在不同的 workspace 和 tab 切换的时候，需要很长时间切换页面，加载会话很费时间。有什么办法优化吗？”

## 范围与行为

- 增补布局恢复基线：桌面和移动端共用布局 store，切换时优先使用已有工作区布局缓存，立即挂载目标内容，同时请求服务端校验；没有缓存时维持加载态。浏览器记住的有效活动 Pane、Tab 和终端布局优先于缓存中的其他客户端焦点。
- 当前布局的本地改动同步进入已有缓存；切换和迟到请求不得把其他工作区数据写入当前布局。目标 Tab 的导航优先于缓存焦点，后台校验保留用户最新选择。
- Review 修正：缓存导航后用户主动选择有效 Pane（包括再次选择当前 Pane）或 Tab，撤销尚未完成的旧导航目标；后台响应不得再次抢回焦点，无效 Pane 请求不撤销合法目标。
- 后台校验包含 `diffSettings` 的更新与清除，即使 Pane/Tab 树未变化，也接收服务端 Git 面板开关、宽度及视图设置；不改变焦点保护及持久化字段。
- 移动端预取、导航菜单刷新、Tab 重排与内容恢复共用已有工作区布局缓存，删除组件私有布局缓存。保留打开菜单时的刷新；迟到的预取不得覆盖请求期间已更新的共享缓存。
- 后台刷新失败保留已显示的缓存并提示失败；不得因为有缓存时的刷新失败自动新建 Pane。无缓存的原有重试行为保留。
- 增补 PERF-OPEN-03：复用不可变时间线条目的工具分组计算，缓存切回及追加消息不重复计算未变化补丁的差异。缓存使用弱引用，随源记录释放；不同对象即使 ID 相同也重新计算，保持工具状态、数量、顺序、补丁详情和展开行为。
- 保留服务端布局持久化、WebSocket 重新初始化、会话身份校验、12 项/2 MiB/5 分钟展示快照上限、分页和待确认消息约定；不保活隐藏终端，不新增后台连接或用户设置。
- 本轮针对已确认的客户端重复等待和重复计算。没有现场计时的服务端检测、网络和浏览器首次渲染耗时不宣称消除。

## 验收标准

1. 缓存工作区在未完成布局请求时已可展示；冷工作区仍等待请求，不能显示旧工作区内容。
2. A → B → A 保留本地 Tab/Pane/终端布局，显式目标 Tab 优先；后台更新可删除已不存在的 Tab，并保留有效当前焦点。
3. 快速切换时旧响应及旧失败不覆盖当前布局；后台失败保留缓存并提示，重试可恢复；无目标和空布局保持正确。
4. 同一条目重复分组、缓存切回和追加其他消息不再次运行其差异计算；更新后的条目重新计算，分组和补丁输出与原行为一致。
5. 运行相关回归、完整 TypeScript、改动文件 ESLint 和构建；记录可控等待/计算次数证据，不将自动化结果等同于真实设备耗时。
6. 延迟 GET 期间切换 Pane 后，未变化/已变化布局响应都保留最新焦点；当前 Pane 重选取消旧目标，无效 Pane 不修改焦点。
7. 相同布局树下，`diffSettings` 更新或变为缺省均正确同步，并保留用户活动 Pane/Tab。
8. 挂载真实移动端布局，完成目标工作区预取后首次切换，在后台 GET 未返回时已显示目标内容；菜单刷新和共享缓存更新可见，迟到预取不覆盖新布局。

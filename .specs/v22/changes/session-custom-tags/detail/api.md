# 标签接口与存储

## 存储

`sessionWorkflow.tags` 为 `{ id, name, color }[]`，`sessionTags` 为 `Record<会话身份, 标签 ID[]>`，`tagsRevision` 为非负修订号。字段可选，缺失视为空目录、空关联、修订号 0。标签颜色为 purple/coral/pink/gray；名称 trim 后为 1–24 个 Unicode 字符，忽略大小写去重。单会话最多 100 个标签、目录最多 500 个标签；接口数组有相同边界。

GET /api/workspace 返回上述数据，写入复用全局 workspace 锁、原子文件替换和 workspace 广播。界面不单独加载目录，不引入逐项目请求。标签筛选条件不写服务端。

## 写入

PATCH /api/session-tags 使用严格校验的操作联合，均携带 `revision`：

- `action: assign`：`key`、`tagIds`、`newTags`；新标签使用客户端生成的稳定 ID；目录创建和关联一次原子保存。会话须属于现有索引或当前活动 Tab，并排除隐藏/已删除身份。
- `action: create`：`tag`。
- `action: update`：`tag`，要求 ID 已存在。
- `action: delete`：`id`，解除所有会话关联，保留会话和工作状态。

成功返回完整 sessionWorkflow；客户端立即应用并补拉 workspace，以收敛并发广播。400 表示格式错误，404 表示目标不存在，409 表示修订冲突/重名/引用已失效，500 表示存储失败；返回稳定 code 供本地化提示。异常不得泄露文件路径。

## 身份与并发

目录、关联或 Tab 绑定发生变化时推进标签修订号（已启用标签数据后）。无原生身份的临时标签在绑定时迁移并消费，合并目标已有标签；已删除目标仅消费，不继承。后续同 Tab 绑定新会话不能携带已消费的标签。客户端未同步时只允许临时展示首次绑定的 fallback 标签。

每次绑定原生身份均清理该 Tab 的临时会话索引，包括已绑定过其他会话、绑定前清空标签、目标已隐藏的情况。索引清理独立于首次人工状态迁移和临时标签是否存在，防止残留空会话参与列表及工作区汇总。

编辑器携带打开时的修订号；其他窗口或身份同步期间变化导致 409，提示关闭后重新打开，不能以自动重试覆盖新值。普通网络/存储失败保留草稿、允许重试。重新发送已成功但响应丢失的创建请求也会发生冲突，避免重复创建。

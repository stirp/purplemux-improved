# 工作区定时任务

## 原始需求

用户询问「purplemux 怎么去增加定时任务呢？」；确认定时执行 Claude/Codex 提示词和 Shell 命令「两种都需要」。

## 范围与行为

- 新增工作区定时任务，桌面工作区菜单和移动端工作区操作菜单提供统一管理弹窗。支持新增、编辑、删除（显式确认）、启用/暂停、立即执行和查看最近执行记录。
- 类型为 Shell、Claude Code、Codex。任务名称、绝对工作目录、命令/提示词、超时分钟数（1–1440，默认 30）必填。默认目录取工作区首个目录；保存及执行时验证目录存在，不沿父目录回退。任务在独立后台进程运行，不依赖标签页或浏览器连接。
- AI 使用非交互 CLI，每次新会话，不恢复已有会话；提示词通过 stdin 传入，不插入 shell 命令。复用现有 Agent 环境配置。Claude 使用 `-p --permission-mode dontAsk`，Codex 使用 `exec --sandbox workspace-write -c approval_policy="never"`；不新增跳过权限开关。模型和登录沿用各 CLI 配置。CLI 未安装、未登录、权限拒绝等保留实际输出，不将进程退出码 0 解释为业务目标已完成。
- Shell 使用用户默认 shell 的非交互登录模式执行命令。输出合并 stdout/stderr，展示为纯文本；完成后保存输出末尾 16 KiB，截断有标识。进程非零退出、启动失败、超时均记录失败原因；超时和服务正常关闭终止进程组。独立 Node 监护进程通过 IPC 感知服务退出（包括崩溃），清理执行进程组，避免服务重启后遗留任务继续执行。
- 支持单次（明确带偏移的时间）、每天、每周（0–6，周日为 0）。周期任务保存 IANA 时区及 HH:mm，默认浏览器时区；夏令时缺失的时刻只跳过该次，继续查找后续有效日期，不能因此停用周期任务或拒绝创建/启用；重复的本地时刻只执行一次。单次任务自动触发后停用；手动执行不消费未来计划。
- 服务端每 15 秒检查到期任务。超过 60 秒的到期时间视为错过，不追赶执行；重启恢复时错过的时间不补跑。周期任务推进到下一个时间，过期单次任务停用。运行中的同一任务不重入，人工执行返回 409，自动到期跳过该次。
- 执行前原子保存 running 记录及推进计划，成功持久化后才启动子进程。进程崩溃/重启后旧 running 记录标记 interrupted，不自动重试。全实例最多同时执行 4 个任务，繁忙时自动到期记录 skipped，人工执行返回 409。
- 进程完成后若结果持久化失败，在调度单例中保留原始结果及实际结束时间；每次调度和手动启动前重试写入，其他任务完成时也可合并写入。仅重试结果保存，不重跑任务；成功后释放运行状态，恢复编辑/删除及并发额度。正常关闭时再尝试保存一次，不无限等待故障存储；若进程退出前始终无法写入，沿用重启 interrupted 语义。
- 任务和最近 10 条执行记录保存到 `~/.purplemux/workspaces.json` 可选字段 `scheduledTasks`，复用现有锁、原子写入和广播；旧文件默认空列表。每实例最多 50 个任务。名称最长 80 字符，内容最长 16000 字符；不记录 Agent 环境变量。成功删除工作区时，锁内清理其未运行任务及记录；运行中（含等待结果持久化）的任务停用未来计划并保留占用，完成并保存结果后清理。启动恢复、调度及创建/修改任务时同步清理历史孤立任务；创建前清理与额度判断在同一锁内，不能让不可见的未运行任务永久占用额度。其他工作区、旧配置及删除失败时的数据保持不变。
- 运行中允许暂停（只影响未来调度），禁止编辑和删除。暂停不终止当前执行。读取或保存失败明确反馈，保留草稿；打开、刷新和重连不会执行任务。管理页轮询、聚焦和重连刷新。
- 新增行为不改变既有快捷命令、终端交互、工作区层级、标签页创建与目录回退规则。不提供 cron 表达式、分布式调度、通知、任务依赖或自动补跑。

## 验收标准

1. 三种类型可创建/编辑/持久化，旧配置兼容；并发任务修改不覆盖其他工作区字段。
2. 单次/每日/每周在指定时区正确计算；覆盖跨日、夏令时、过期/暂停恢复与手动执行。
3. 调度和手动执行原子互斥；覆盖重启 interrupted、不补跑、运行重叠、容量限制和持久化失败不执行。
4. Shell 实际执行验证成功、非零退出、输出截断、超时、目录失效；AI 用可控 CLI 替身验证参数、stdin 和环境隔离，不调用收费模型。
5. API 拒绝非法任务、跨工作区 ID、未知操作；遵循现有登录/CLI token 认证；错误不报告成功。
6. 桌面/移动端均可管理和查看记录，错误保留输入，删除显式确认，窄屏无横向溢出。
7. 相关自动化测试、完整 TypeScript、改动文件 ESLint、构建和浏览器检查记录真实结果及限制。
8. 纽约每周日 02:30 的任务在 2026-03-01 执行后，下一次为 2026-03-15 02:30；覆盖创建/重新启用以及自动执行后的推进，不能误报 past 或停用。
9. 模拟任务结束后连续写入失败再恢复，验证结果/退出码/实际结束时间保留，自动重试和手动启动前重试均有效；四条待写结果恢复后不再占用并发额度，任务未重复执行，修改和删除恢复可用。
10. 删除工作区与恢复历史孤立任务后可继续创建任务；其他工作区的 50 条上限仍有效。删除失败不清理，运行中任务不提前释放并发额度，结果保存后安全清理。

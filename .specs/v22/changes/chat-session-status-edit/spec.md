# Chat 内修改会话工作状态

## 用户原始需求

“我需要能在chat界面修改会话状态的能力”，用户确认在 Chat 顶部会话信息栏右侧增加可点击状态标签的方案：“可以，就这么改吧”。

## 范围及覆盖关系

- 为 Claude、Codex 桌面 SessionMetaBar 及移动端独立面板增加共用头部和工作状态选择入口；移动端详情继续使用原有 Sheet。
- 增量扩展信息栏的展示与交互：信息区域和详情展开保留，状态选择为独立操作，不触发详情展开。
- 沿用会话工作状态基线的人工优先、自动推导、身份迁移、持久化、广播与重连规则；不修改运行状态、模型执行或工作区聚合算法。
- 不改变 Sessions 列表现有入口、会话标题、终端视图或原生会话文件；不新增接口、依赖或存储字段。

## 界面与流程

1. 信息栏右侧显示当前工作状态及下拉箭头，菜单包含未开始、进行中、审批中、已完成、自动判断。自动模式下标签展示实际推导状态，菜单选中“自动判断”；该选项用于恢复自动规则。
2. 选择后立即通过现有 `PATCH /api/session-workflow` 保存，成功后更新共享状态并沿用 workspace 广播；保存期间禁用重复操作。失败提示且保留原状态。
3. 状态以 provider + 当前显示会话 ID 定位；尚无 ID 时使用当前 Tab fallback，沿用首次绑定迁移。不同 provider、同 Tab 的前后会话不得串写。
4. 元信息加载/恢复、断连、当前 Tab 与显示会话身份不一致、首次 fallback 人工状态尚未迁移、已删除或无法解析目标时禁止修改；已有缓存信息仍可展示。切换身份关闭旧菜单。
5. 状态按钮与详情区域互为独立交互，不嵌套按钮；提供键盘选择、焦点反馈、文字标签和当前选择反馈。
6. 窄屏优先压缩信息区域，状态文字保持完整，触摸入口至少 44px 高；信息区域不足 360px 时只展示截断标题，分支、费用和上下文用量仍保留在详情中。按容器宽度适配桌面分屏和移动端，沿用主题及低饱和语义色。
7. 标记已完成不停止模型；后续模型运行不覆盖人工状态。恢复自动后重新按共享规则计算。
8. 保存开始和结束不得重建选择器。菜单关闭后焦点回到同一触发器，保存成功或失败均可继续使用键盘；保存期间禁止重复操作但保留触发器可聚焦。用户主动移焦或切换会话后，迟到的保存结果不得抢回焦点；失效身份的旧菜单仍须关闭。
9. 桌面详情已展开时，状态菜单内点击选项、保存或按 Escape 关闭菜单均保持详情展开；Escape 先关闭菜单，菜单关闭后再次按 Escape 才关闭详情。真正点击信息栏及菜单之外时仍关闭详情。

| 编号 | 条件 | 验证方式 |
| --- | --- | --- |
| CE-01 | Claude/Codex Chat 顶部都有状态入口，终端及会话列表保持原样 | 组件测试、构建/浏览器 |
| CE-02 | 四种人工状态和恢复自动正确保存，自动标签显示实际阶段 | 真实菜单交互测试 |
| CE-03 | 保存等待防重、失败保留原值并提示、共享状态更新 | 组件及既有同步测试 |
| CE-04 | provider/会话隔离、无 ID fallback/首次迁移、新身份不继承旧状态 | 组件及既有工作状态测试 |
| CE-05 | 加载、断连、缓存身份过期及删除目标不可修改 | 组件测试 |
| CE-06 | 状态菜单不展开详情，详情仍可独立展开，键盘操作可用 | 真实组件交互测试 |
| CE-07 | 窄屏状态文字及触摸入口可用，浅深色保持可辨识 | 浏览器或明确记录验证限制 |
| CE-08 | 相关测试、完整 TypeScript、改动文件 ESLint 通过 | 命令记录 |
| CE-09 | 保存成功/失败后焦点保留，保存期间不重复提交，主动移焦/切换会话不被抢焦点 | 真实组件焦点回归测试、浏览器 |
| CE-10 | 展开的详情不被状态菜单的 Portal 点击及 Escape 意外关闭，真正的外部点击和后续 Escape 仍能关闭详情 | 真实组件交互测试、浏览器 |

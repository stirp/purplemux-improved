# 一键完成提交与 PR/MR 交付

## 用户需求

在现有分步流程上，每个阶段提供一个完成后续流程的按钮：没有提交信息时 AI 生成、提交、推送并发起 MR；人为填写信息后直接提交并发起 MR，MR 信息复用提交内容。

## 行为约定

- 保留原分步入口，新增明确列出后续操作的一键按钮；点击即授权本次剩余流程，不再逐步确认。替代基线中一键路径也必须分别确认推送和草稿的约束，原分步确认不变。
- 无标题时生成提交信息，再使用生成快照提交；已有非空标题则跳过 AI，使用当前标题、正文。仅填写正文时保留正文，AI 补全标题。
- 正在单独生成时允许选择生成结束后继续提交与交付；不发起第二次生成。运行中的提交、推送和创建禁止重复触发，期间不能关闭弹窗。
- 提交成功后 PR/MR 使用实际提交的标题和正文，不再调用文案生成。分步提交同样预填这份内容，仍可编辑。
- 提交后提供“推送并发起 PR/MR”；当前弹窗确认推送成功后提供“发起 PR/MR”，创建失败重试跳过已完成推送。变更 HEAD 或远程后不沿用旧推送状态。
- 沿用既有远程、平台和目标分支默认值；缺少配置时停在可编辑的交付表单，填写后点击继续。既有提交发布保留文案编辑和 AI 生成入口；一键续办时若缺少标题，先基于已提交差异生成草稿信息。
- 逐步显示生成、提交、推送和创建进度，任一步失败停止；提交结果未知禁止继续交付。提交成功但后续失败保留提交结果和文案，不能重复提交。
- 复用工作区身份匹配、快照、阻断状态、远程验证与草稿去重逻辑。不自动合并 PR/MR，不 force push，不新增服务端 API 或配置字段。
- 桌面和移动端共享按钮，长文案可换行。

## 验收标准

1. 空标题一键依次生成、提交、推送、创建草稿，标题正文一致；手填标题跳过 AI，仅填正文保留正文。
2. 单独生成期间的一键续办不重复生成；生成失败不提交，提交失败或结果未知不推送。
3. 分步提交预填内容，一键路径不出现逐步确认；原分步确认仍生效。
4. 推送失败不创建；创建失败保留推送成功状态，再次点击只创建；变更远程或 HEAD 重新推送；已有草稿链接和关联保存警告保留。
5. 缺少远程/目标或身份不符不能发布；快照变化、脏状态等服务端保护保持生效；重复点击及关闭受保护。
6. 相关测试、完整 TypeScript、改动文件 ESLint 及构建或浏览器验证有实际证据。

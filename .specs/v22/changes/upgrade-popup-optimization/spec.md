# 升级提示支持跳过版本与强制升级

## 用户原始需求

“升级弹窗要支持跳过此版本，以及强制升级。因为很多远期会话都是长期存在的，现在这个重启条件就没法升级了。”

## 范围与行为

- Web 工作区更新提示、系统设置及 Electron 原生检查更新弹窗均提供跳过此版本与强制升级入口。
- 替代基线中更新提示必须持续可见的约定：跳过当前检测到的新版本后隐藏该版本的工作区自动提示，设置页仍显示该版本已跳过且允许手动升级。后续检查不恢复同版本提示，更高版本正常提示；跳过不触发下载或重启。
- 跳过版本保存在 `~/.purplemux/workspaces.json`，按 server/desktop 区分，刷新及重启后保留；旧配置无该字段等同于未跳过。复用工作区存储锁与原子写入，保存失败显示错误且不能假装已跳过。跳过已下载版本后解除下载缓存对后续版本检查的固定，不删除磁盘包。
- Electron 检测到本机后台服务时，将桌面偏好保存交给该服务串行写入，避免两个进程并发覆盖工作区。后台服务尚未就绪或旧服务不支持该操作时明确报错，不回退为直接写入；无本机服务及服务锁时，远程模式在本机保存。该请求只发往本机，不修改所连接的远程服务。
- 普通升级继续执行下载前及重启前两次空闲检查，不改变工作树同步、会话回收等其他安全判定。
- 增加“强制升级并重启”：明确确认目标版本和任务可能中断、连接会断开的风险后，单次操作跳过两次空闲检查。此授权不保存为全局设置，失败后的普通重试仍执行检查。
- 强制升级仅绕过会话检查；继续执行版本、运行模式、下载校验、安装及原生准备要求。确认期间目标版本改变时拒绝该次强制操作，要求重新确认。保持退出时分离 PTY、保留 tmux 和工作区的既有机制，不主动结束会话。
- skip 与 force-install 使用固定动作及服务器已检测版本，不接受命令、URL 或目录。保留 HTTP 鉴权、JSON/请求头及 Electron 来源校验；重复请求不重复下载或重启，普通升级进行中不被强制请求升级权限。
- 本机偏好转发使用 `skip-desktop-version` 固定动作，仅接受稳定版本字符串并保存 desktop 偏好，不执行检测、下载或重启，不改变 server 跳过版本。
- 下载中、检查中、重启中禁止新操作。跳过及强制升级保存/请求错误可见。桌面和移动端共用交互，操作可换行。
- Review P1 修正：Electron 主入口不能静态加载工作区存储及其服务端依赖。各启动模式（内嵌服务、复用后台服务、远程连接及开发入口）均先完成 Shell 环境解析与 pristine 环境捕获，再初始化 standalone 依赖搜索路径；偏好读写按需加载存储，不提前固化 Shell 环境。
- Review P2 修正：状态区分版本检测与用户安装前的空闲检查。后台检测尚未发现更高版本时，已跳过版本的工作区提示持续隐藏；手动安装的检查、下载及重启进度，以及错误/阻断仍可见。

## 验收标准

1. 跳过版本可持久化、重新创建管理器后同版本仍跳过；更高版本恢复提示，设置页可手动安装已跳过版本；读写失败不隐藏提示。
2. 跳过拒绝过期或非法版本及执行中的安装；已下载且阻断后跳过，不阻止检查下一版。
3. 普通升级遇忙碌/未知仍阻断；强制升级经确认可绕过两次检查，复用已下载包且只安装一次；失败后普通重试不继承强制权限。
4. 强制升级仍拒绝不支持的运行方式、无新版和过期版本；下载/原生准备失败不重启。
5. HTTP、IPC 与 hook 传递相同动作和版本；原生与 Web 确认取消不安装；原有来源保护保留。
6. 相关单测、完整 TypeScript、改动文件 ESLint、构建或浏览器检查记录实际结果；不执行用户实例真实升级重启。
7. 模拟无根目录 node_modules 的正式包主入口，确认可进入 bootstrap 前的注册阶段，且不会提前访问服务端依赖或写入 pristine 环境；验证 standalone 模块路径解析与延迟加载。
8. DOM 回归覆盖已跳过版本的后台 checking/available、发现更高版本、主动安装检查/下载/重启，以及错误可见性；管理器测试验证 HTTP/IPC 即时快照携带安装状态。

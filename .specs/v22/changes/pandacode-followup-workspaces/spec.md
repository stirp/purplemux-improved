# PandaCode 调研后续工作区准备

## 用户原始需求

“好，就按照你说的顺序，把每个问题在 purplemux 建立对应的工作目录”。

## 范围与约定

- 以 purplemux-improved 主工作区为父级，按调研报告第 7 节的 10 项建议依次创建独立分支、Git worktree 和注册工作区。
- 工作区名称包含顺序、优先级和任务名；需求 ID 使用业务名称，不使用连续编号。
- 每个工作目录新增独立的规格草稿和任务清单，记录目标、范围、基线、前置依赖、验收与调研来源。
- 最后一项是技术预研，评估索引、按轮 adapter 和预热；不视为授权直接替换生产架构。
- 本次为后续任务建立工作环境，不启动编码任务、不提交或推送、不改变已有工作区文件。

## 验收

1. 10 个工作目录存在，分别绑定不同分支并注册为主工作区的子工作区。
2. 创建时以核验的 main 提交为基线，记录实际 HEAD；不复制其他任务未提交修改。
3. 每项有自己的 spec.md 和 task.md，内容与报告顺序一致，链接和前置依赖可定位。
4. 记录创建结果、工作区 ID、路径及检查结论；不把准备完成写成代码实现完成。

创建结果见 [result.md](./result.md)。

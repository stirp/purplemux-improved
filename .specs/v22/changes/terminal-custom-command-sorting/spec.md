# 终端自定义命令拖动排序

## 原始需求

terminal的自定义命令无法排序, 请在设置界面上增加拖动排序的能力

## 范围与行为

- 在终端命令栏齿轮打开的管理设置弹窗中，为命令增加拖动手柄；桌面鼠标、移动端触摸均可调整顺序，手柄支持键盘空格开始/结束、方向键移动、Escape 取消。
- 拖动仅从手柄启动，编辑、删除及命令内容区域保留原交互；触摸手柄外仍能滚动弹窗。空列表和单条列表不提供有效排序操作。
- 松开到其他条目后自动保存；取消、原位放下或无有效目标不发送请求。保存期间禁用管理操作与关闭弹窗，读取失败时禁用排序。
- 拖动期间禁用新增、编辑和删除，避免切换表单或删除条目中断拖拽上下文。Escape 从当前手柄传递给拖拽传感器，只取消拖动并保留弹窗；取消后可再次拖动、编辑或正常关闭。方向键同样须能从手柄传递，不能被弹窗拦截。
- 保存成功后管理列表及终端按钮栏同步采用新顺序；保存失败保留原顺序并显示排序失败提示，允许重试。排序不执行命令，终端断线仍可管理顺序。
- 复用 `terminalCommands` 数组顺序，不新增排序字段或配置迁移；新增仍追加末尾，编辑不改变位置，删除保留其余条目相对顺序。
- 扩展 `PUT /api/terminal-commands`，请求 `{ ids: string[] }`，成功返回排序后的完整列表。ID 必须非空、长度不超过 100，最多 50 条且不重复；格式错误返回 400。
- 排序在既有工作区文件锁内读取最新命令，仅变更顺序并保留最新名称、内容及其他配置；ID 集合与当前列表不一致返回 409，不覆盖并发新增或删除。失败后客户端重新读取列表；同时排序以最后一次成功写入为准。
- 保留基线的执行、校验、读写失败、广播、聚焦及重连刷新约定；本增量仅扩展管理操作和排序 API。

## 验收标准

1. 三条以上命令可通过手柄上下拖动；桌面鼠标、手机尺寸触摸及键盘排序可用，移动端无横向溢出。
2. 保存后按钮栏顺序与设置列表一致，刷新/重读文件保留；新增、编辑、删除不破坏排序。
3. 取消、无效拖动和原位放下不保存，编辑/删除不误触拖动，排序不发送终端输入。从聚焦手柄发出方向键可移动、Escape 可结束拖动且不关闭弹窗；拖动期间不能进入编辑/新增或删除，取消后这些操作及关闭恢复。
4. 保存失败显示反馈并保留已保存顺序，重试成功；加载失败、保存中、少于两条时禁用排序。
5. API 拒绝重复、非法或过量 ID；过期集合返回 409，并发修改内容和其他配置不丢失；写入失败不广播、不改变文件。
6. 桌面/移动共用组件，沿用 SWR 和工作区同步机制；旧配置无需迁移。

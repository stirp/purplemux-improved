# Worktree 合并确认就地展开

## 用户原始需求

“所有的合并确认对话框都在最上面，有时候操作距离太远了，这个确认应该就地展开。”

## 范围与行为

- Worktree 管理的关系与同步视图中，“将子合并到父”和“将父合并到子”都在所操作的关系卡片内、操作按钮下方展开确认区，不再在列表顶部展示。
- 确认区归属以父子工作区 ID 匹配；刷新重建关系对象后仍属于原关系，不漂移到其他卡片。
- 确认所属父子关系因工作区删除或改挂而消失时，自动清除确认状态，释放其他卡片的合并入口；不依赖仓库刷新成功。仅切换视图或刷新仍存在的关系时保留确认。
- 同时只展示一处确认区，保留来源、目标名称及确认/取消按钮。取消收起后可以操作其他卡片；确认执行后按原流程收起和刷新。
- 桌面与移动端共用实现；长名称允许换行，确认按钮组可换行，不要求回到列表顶部确认。
- 本增量细化基线的确认位置；显式确认、单次操作互斥、快照复核、主工作树保护、错误保留、冲突恢复和视图切换保留状态沿用基线。无接口、存储或 CLI 变化。

## 验收标准

1. 多卡片列表的后部卡片点击任一合并方向，确认区只出现在该卡片的操作按钮之后，列表顶部与其他卡片不展示确认。
2. 展开本身不执行 merge；确认文案与最终请求的来源、目标及 HEAD 一致。
3. 取消后确认区消失且不发起 merge，可在另一卡片重新展开；执行期间确认/取消及其他合并入口禁用。
4. 确认展开时刷新仍位于原父子关系内；合并完成后收起，原失败提示及刷新行为保持正常。
5. 完整 TypeScript、改动文件 ESLint、相关回归通过；通过构建或浏览器验证并如实记录移动端/实机验证限制。
6. 展开确认后切换仓库视图并删除所属工作区，返回关系视图可操作其余卡片，无需重开弹窗；刷新失败不阻止清理，关系恢复时不复活已失效确认。
